Switchelp × 决策模型：六个可以立刻加进去的玩法

Jev（TypeSafe）与前天 OpenAI DevDay 的 Decisions API（Luna）把「只做判断、不写作文」的模型变成了一个独立品类。 对 Switchelp 来说，这类模型不需要联网、不需要 TypeSafe 账号：把开源 Laya 下载一次放进应用（约 260 MB，Apache-2.0）， 它就是你的本地裁判、本地守门员、本地雷达。下面每张卡都是一个能加进现有页面的功能，都配了一个能点的 Demo。

本地推理，判断不出网 零新增费用（自带模型） 不读你的会话内容 Demo 数据为模拟，已标注
玩法 01

模型擂台：让别人说"哪个模型好"，你用自己的题说话

同一个问题，并排发给 2–4 个供应商，本地小模型当裁判，按你自己的偏好打分出榜。

落在：概览页 / 网关页（新增「擂台」页签） 用你已有的 Key 榜单存在本机
题目：把这段 Python 改成类型安全写法，并解释为什么
裁判偏好
点右侧按钮开始对打，看裁判怎么打分与排名。
每个回答的 token 数与耗时是模拟值；裁判分数由偏好权重实时算出——真实实现里这一步由本地 Laya 出分。
为什么好玩公开榜单跟你的活儿无关；自己跑一次，答案常常反直觉（贵的不一定赢）。
推广点"我用 Switchelp 跑了私有擂台，XX 输给了免费模型"——天然可晒、可截图。
诚实提醒裁判也会看走眼：分数旁必须带置信度，低置信标「难分」。别把它当真理。
玩法 02

闸门：八成请求根本不值得惊动大模型

网关里加一道本地闸门：把握够高就直接放行（不转发），拿不准才交给大模型。

落在：网关页（默认 shadow，只记录不拦） 这是社区实测唯一真正值钱的用法

拖动阈值：越保守，放行越少、错得越少、省钱越少。

模拟数据按实测形状构造（40 个判断）：≥0.90 档全对；0.80–0.90 只错 1 个；越低越浑。真实数字来自 X 上那篇长文的第二轮实测：255/255 全对、阈值 0.80 可放行 89%、只错 1 个；同一批测试里它的中位延迟约 0.7 秒，而且最慢也只有 1.5 秒（对照的轻量大模型中位相近但最慢 32 秒）。

为什么好玩它把"要不要花大钱"变成一个可以在滑块上看见的取舍，而不是玄学。
推广点"我的 Codex 里 8 成请求根本没花钱"——比任何性能数字都好懂。
诚实提醒同一批实测里，把决策模型插进 Codex 做模型路由反而多花 59%–184%（代理把请求变重、还弄丢缓存）。所以闸门只做"放行/转交"，不做模型路由。
玩法 03

灵感雷达：给你的资讯流装一个挑食的胃

内容中心每条资讯先过一遍本地判断：真干货 / 标题党 / 情绪诱导 / 广告，按你的挑食度沉底。

落在：内容中心 只排序，不删除 小红书同款玩法已有两万赞
挑食程度 0.60

每条带概率与一句理由；低于阈值的只是沉底（半透明），一条都不会消失——这跟"信息流里被静默吞掉"是两件事。

为什么好玩每个人关心的东西不一样，雷达是"你的口味"，越用越合口味（纠错一条就写进规则）。
推广点博主自己做的同类小工具已经在小红书拿到两万赞；Switchelp 把它做进桌面端，且判断不出网。
诚实提醒中文场景要选多语言版模型；它擅长"这条像不像广告"，不擅长精确的事实核查。
玩法 04

训练你的小裁判：它的本事是你说清楚的，不是它自己会的

你说"这条该这样判"，分歧就写成一条规则；三条规则下去，它从 1/3 对变成 3/3 对。

落在：设置页 → 决策服务（新增「规则工作台」） 对应社区公认的核心难点
任务：这条 issue 该不该进我的待办？

当前规则集 （0 条）

点任意一条的「判错了」按钮，把它变成一条规则。

一致度 1/3 —— 你纠错几条，它就跟着变。
为什么好玩像一个"教会实习生"的小游戏，看得见每次纠错的效果。
推广点这是把小红书上作者亲口说的经验（"判错的地方全部写回规则，要多次校对"）做成了产品里的一个界面。
诚实提醒它不会自己想明白你的偏好；如果你懒得写规则，这个功能就不该开。
玩法 05

发出去之前：先体检，再决定发给谁

把要发出去的提示词先过一遍：已知密钥格式用规则硬挡（真的在跑），模糊情况才让本地模型判断。

落在：网关页（出站体检，可关） 规则先行，模型只处理灰区
右侧高亮为真实正则命中；下面的判断卡为本地模型的示意输出。
为什么好玩点一下就能看见"我差点把什么发出去了"，比读十页隐私政策有用。
推广点"Switchelp 会在你把它发给第三方中转之前提醒你"——这是切换供应商场景里真实存在的风险。
诚实提醒它只能减少、不能消灭泄露；规则命中要 100% 拦，模型判断只在 0.30–0.80 之间问你，超过 0.80 建议拦。

附录 B

几个必须知道的坑（不然会白做）

1. 别用它做模型路由省钱 —— 有人实测反而多花 59%–184%

X 上那篇长文的作者把决策模型插进 Codex 做"挑便宜的模型跑"，结果中间代理把请求变重 2.5 倍、还弄丢了 cache，每步多等 1–2 秒。他自己和另一份公开 holdout 都得到同一个结论： 按轮次换模型比一个强模型跑到底更贵。闸门（放行/转交）可以，路由（换模型）不行。

2. 别让它做压缩/"挑重点" —— 它看不到内容就只会瞎判

同一篇实测里，把它塞进上下文压缩插件的结果是"无脑删"：为了塞进它的 3.2 万 token 上限，插件先把内容砍光了，它只看到文件名和长度。社区里另一个"用模型写会话摘要"的项目也发现， 摘要式交接的召回率反而低于原文。要判断得先看得见；要看得见就超上限——这是它天生的夹缝。

3. "置信度 90%"不是"九成正确" —— 尤其在你自己的语料上

官方承认校准是群体级别的，不给推荐阈值；社区实测里出现过"最错的答案置信度最高 0.86"，本地开源模型更夸张（量化后在 39 条输出里 37 条是精确的 0 或 1）。 所以：阈值只能自己测（玩法 06 就是干这个的），界面里永远写"把握/概率"，不写"正确率"。

4. 中文要选多语言版模型，别用英文版硬撑

TypeSafe 官方承认中文"支持但不同等好"；开源 Laya 的英文版在多语言场景明显掉点（多语言版约 524 MB，是英文版两倍）。Whitelist 里也不要放许可证不清的权重： open-jev 系是 CC-BY-NC（非商用），有个别复刻压根没有许可证。

5. 别把 260 MB 直接塞进安装包

当前更新包 7.34 MiB，塞进去会变成约 280 MiB（36 倍），而且 macOS 上还会把最低系统版本从 12.0 抬到 14.0。做法：首次使用时下载 + 用应用已有的签名校验， 校验不过就退回"借道用户已有供应商"的在线判断。
