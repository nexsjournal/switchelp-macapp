工具：`.zcode/skills/design-conformance/scripts/in-page-audit.js`（本次按 SKILL.md 自述的排除规则修正过三处，
见第 4 节）。表面覆盖：六个侧栏页、首次接入向导、整页模型编辑器、供应商弹窗（新建 / 编辑 / 更多菜单开）、
获取可用模型弹窗、添加与编辑模型弹窗（含高级配置展开）、删除模型确认、删除供应商确认、应用到 Codex 的

## 1. 修掉的问题

### 1.1 弹窗头部与底栏之间多出一条分隔线（用户实拍）

**现象**：确认类弹窗（重启 Codex、放弃修改、删除、清空日志…）在描述与底栏之间多出一条横线，
看起来像「两条分隔线」。

**实测**：重构前 `[role="dialog"]` 内，头部 `border-bottom` 与底栏 `border-top` 之间隔着
**24px 的空白正文带**（`.form-fields` 的 padding），两条线相距 24px。重构后两线**同一条位置**：
头部 bottom = 471、底栏 top = 471，正文高度 0。

**规范出处**：`docs/design/03-components.md` Toast/Dialog 行；`.form-footer` 的注释
「底栏属于滚动区之外」（`src/styles/global.css:106`）。

**影响**：视觉上像两道分隔，且底栏在滚动内容里、长表单会盖住最后一个字段。

**修法**：8 处 `<div className="form-fields"><div className="form-footer">` 改为 Dialog 的 `footer` 槽
（App、SettingsPage、CodexConfigPage、ModelEditorPage、ModelsPage、LogsPage、ProviderForm ×2），
两处只读弹窗（模型探测结果、日志事件详情）的关闭按钮同样移入底栏。

### 1.2 差异/确认卡片渲染在页面最下面（真机上导致「还原没生效」）

**现象**：点「还原为原生 Codex」之后，用户看不到任何可确认的入口；他接着点了旁边的「重启 Codex」，
而那条路只重启、不写配置。数据库里那条还原事务停在 `prepared`（只生成了计划，从未执行）。

**实测**：该卡片是页面里的 `<section>`，位于操作行**之下**；在 1280×840 视口里需要向下滚动才可见。

**影响**：功能上等于不存在——用户以为还原失败。

**修法**：差异与确认改成模态弹窗（`CodexConfigPage`），底栏固定、差异表格在正文里滚动；
确认后关闭弹窗并继续走「写入 → 重启宿主 → 结论」这条链。

### 1.3 计划过期会死路（Codex 自己会改配置）

**现象**：`config.toml` 里有 `[projects."…"]` 这类条目——那是 **Codex 自己**在启动时写的。
于是「先生成计划 → 再重启 Codex → 再确认」这个顺序必然让 `expected_config_hash` 对不上，
`execute_*` 被判成配置已变更而拒绝写入。

**修法**：前端在收到 `CONFIG_CHANGED` 时**自动重新生成计划并重试一次**（应用与还原都只碰本工具
自己的受管字段，重放安全），并提示「Codex 自己改过配置文件，已重新生成计划并继续」；
重试仍失败时把原因留在弹窗里，不谎称已提交。回归用例两条。

### 1.4 字号不在字阶上（36 处）

**现象**：审计 `fontsUsed` 显示页面里出现 10px / 11px / 19px / 20px。

**规范出处**：`docs/design/02-icons-type-and-copy.md` 的字阶表最小一档是「辅助说明 12/18」，
且同一页明写**「正文不小于 12 px」**。

**修法**：36 处 10/11px 统一回到 `var(--font-size-caption)`；侧栏品牌 19px → 区域标题（18），
首页「当前生效模型」20px → 数值强调（24/32）。复测后各页字号集合为 12/13/14/16/(24)/28，
全部落在字阶内。

### 1.5 表格里 32px 点击区被滚动容器裁掉

**现象**：审计 `clipped` 报 `.tableWrap` 裁掉 `span.checkHit` 7px、`button.sortButton` 4px。

**原因**：这两个控件的 32px 点击区是靠负外边距撑出来的（`margin: -7px` / `-5px 0`），
而 `.tableWrap { overflow-x: auto }` 会把越出边界的那几像素裁掉——点击区实际少了边。

**修法**：按规范给滚动区留白：`.tableWrap { padding: 7px; margin: -7px }`。复测 `clipped` = 0。

## 3. 审计脚本本身的修正（三处）

脚本的规则与 SKILL.md 的自述不一致，继续跑只会产出噪音；按自述修正：

1. **`clipped` 只报不可达的裁切**：祖先 `overflow: auto|scroll` 时越界内容滚一下就能看到，
   那是滚动区在正常工作（弹窗正文、表格横向滚动都靠它）；只有 `overflow: hidden` 才算真被锁住。
2. **绝对/固定定位不参与重叠判定**：SKILL.md 的噪音清单里有这一条，脚本漏了。字段右侧叠加的
   「显示密钥」按钮、菜单、Toast 都属此类。
3. **紧贴判定看内容是否也贴住**：相邻盒子之间有内边距（≥8px）或一条分隔线时，视觉上是分开的
   ——滚动区与固定底栏、`<details>` 的 summary 与展开体都靠这个。另外 `[role="switch"]` 规范就是
   36×20，不受 32 方形约束；勾选框图形的点击区由外层（label / 点击层）撑到 32，外层够大即合格。
