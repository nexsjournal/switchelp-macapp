## 0. 结论摘要

**三个页面在两套主题、两种窗口尺寸下：重叠 0、溢出 0、裁切 0、对比度不合格 0、点击目标不合格 0、
每页恰好一个 `<h1>`、无正 tabindex、无横向滚动。**

本轮量出并修掉 3 处真实缺陷，全部由「CSS Module 覆盖全局样式时漏声明属性」引起——这个仓库
已有专门记录（memory: CSS Module 覆盖全局样式的三个坑），本轮又踩中同一类的两个新变体：

| # | 现象 | 实测数字 | 规范条目 | 状态 |
| --- | --- | --- | --- | --- |
| 1 | 插件市场技能卡片三行文字互相重叠 | `skillName` 与 `installedTag` 垂直重叠 **6px**、与 `skillDescription` 重叠 **8px** | 全局 `button { height: var(--control-height) }`（40px）把 grid 行压扁 | 已修（`.skillList button` 显式 `height: auto`） |

弹窗单独按 `[role="dialog"]` 跑：安装确认弹窗（含两行冲突处置）0 违规。

### 1.2 对比度

按 alpha 合成后的真实底色计算，判定线：正文 4.5:1，≥24px 或 ≥18.66px 粗体 3:1。
**两套主题都冷启动各跑一遍**（`?theme=light` / `?theme=dark`），因为热切换后按钮底色仍是旧主题，
量出来的数字会自相矛盾。浅色下 `document.body` 底色实测 `rgb(246, 246, 247)`，确认主题生效后再量。

结果：**三个页面、两套主题，不合格 0 处。**

### 1.3 点击目标

`targetCount` 全为 0（即无违规）：所有 `button` / `a` / `input` / `select` / `[role=tab]` 的实测盒
均 ≥32×32；勾选框图形本身 18，外层 `label.check-label` 撑到 ≥32，符合「点击区」的口径。

### 1.4 结构与键盘

- 每页恰好一个 `<h1>`（工具管理 / 插件中心 / 内容中心）。
- 纯图标按钮无缺名：`iconButtonsWithoutLabel` = 0。
- 无正 `tabindex`；本版三页没有表格，`columnHeadersWithoutScope` 不适用。
- 弹窗：Escape 可关闭（实测 `[role=dialog]` 数量 1 → 0），关闭后焦点回到触发它的「添加技能」按钮
  （实测 `document.activeElement` = 该按钮）。脏表单确认沿用既有 Dialog 实现，未改动。

### 1.5 最小窗口与缩放

960×640 下三页：`documentElement.scrollWidth` = `clientWidth` = 960，无横向滚动；侧栏收窄到 **184px**
（与规范一致）。插件市场的两栏布局（`minmax(220px,300px)` + `1fr`）在该宽度下没有溢出。

### 1.6 字阶

三页实测字号集合：12 / 13 / 14 / 16 / 28px，与既有页面的字阶一致（12 caption、13 caption 强调、
14 正文与控件、16 卡片标题、28 页面标题），未引入新字号。

## 2. 未验证项

- **200% 缩放**：本机未实测该三页在 200% 下的横向滚动（既有审计记录过其他页面此项不合格）。
- **真实安装落盘**：视觉夹具里的「安装」是合成数据，不碰真实技能目录。文件操作的正确性由
  Rust 侧集成测试用**真实临时目录**验证（安装 → 指纹校验 → 卸载往返、冲突不覆盖、路径逃逸被拒、
  改过的文件保留），但没有在真机上对 `~/.codex/skills` 做过一次真实安装。
- **真实抓取**：内容中心三页用的是夹具的合成条目。真实 RSS/GitHub 抓取只在核心单元测试里用假抓取器
  验证过协议与退避逻辑；预置源的**可访问性**是 2026-09-21 用 `curl` 单独核对的一次性事实，
  不等于本应用运行时一定成功。
- **Tab 顺序手动走查**：未逐页手动按 Tab 走一遍（脚本只能查正 tabindex 与缺名）。
- **Windows**：本机只有 macOS，Windows 下的探测路径与技能目录未验证。
- **待应用条遮挡**：三页底部都可能被全局的「待应用」条覆盖（截图可见）。这是既有组件的行为，
  不属于本次新增页面的问题，未在本轮改动；若判定为缺陷应在全局层面处理。

# 第二轮：按用户反馈修的界面问题

用户反馈的五条里四条是界面改动，逐条记录实测证据。第四轮改动同时**关掉了 2026-09-20 审计的 §10（P2）**。

## R1 搜索框里外两层边框（供应商与模型页）

**现象**：搜索框看起来是一个框里套着另一个框，两个框的圆角错开。
**实测**：`.providerSearch` 容器 `border: 1px`、高 40；内层 `input` 也量到 `border: 1px`、`height: 40`、
底色 `rgb(255,255,255)` —— 输入框比容器的内容区（38px）高 2px，压在外框上。
**根因**：`.providerSearch input` 权重 0,1,1，与全局 `input:not([type='checkbox'])` **打平**；
全局样式在打包顺序上更靠后，平手它赢（与既有记录同一条规律）。
**修法**：类名写两遍（`.providerSearch.providerSearch input` → 0,2,1）。
**复测**：内层 `border: 0px`、`background: rgba(0,0,0,0)`、`height: 20`，外层容器仍是唯一的框。

同一处理用于本轮新增页里同样的写法：工具管理 `.searchRow`（修前同样量到双层边框）。

## R2 待应用条从「跨页吸底」改成「供应商与模型页页头下方的一行」

**现象**（用户反馈 + 2026-09-20 审计 §10 已记录的 P2）：底部常驻的待应用条压在内容上，挡住视口底部那一行控件，
而且**每个页面都有**。
**实测（修前）**：`position: sticky`，`z-index: var(--z-apply-bar)`，出现在除 Codex 配置页之外的每个页面。
**修法**：改为普通行（`position: static`，去掉 z-index 与投影），只渲染在「供应商与模型」页、紧跟页头。
**复测**：供应商页量到 `position: static`、`top: 180`（页头 bottom = 148）、高度 72；
工具管理页**查不到** `[role=region][aria-label=待应用]`。
「有几个模型待确认加载」这个事实仍同时出现在顶栏胶囊、概览页与底栏，四处文案同源不变。

## R3 侧栏分组：给「连接诊断 / 日志」补上组标题

**现象**（用户反馈）：内容中心看起来和连接诊断、日志、设置挤在同一组里。
**根因**：只有「扩展」「内容」两个组标题，而「内容」这组之后紧跟着没有标题的「连接诊断 / 日志」——
分隔标签的管辖范围只能靠猜。
**修法**：新增「诊断」组标题（`shell.navGroup.diagnostics`），三组各自有标题、成对出现。
组标题仍是 `aria-hidden`、不可点、不进 Tab 顺序。

## R4 页签换成统一的分段控件

**现象**（用户反馈）：下划线式页签的选中态看着「下面两个角是圆的」，三处页签各写了一套样式。
**根因**：选中态用 `border-bottom: 2px solid var(--accent)` 画下划线，而元素同时吃着全局 `button` 的
`border-radius: var(--radius-sm)`（8px）——下划线跟着圆角弯下去。
**修法**：抽成共用组件 `src/components/SegmentedTabs.tsx`：胶囊容器 + 胶囊选项，
选中态复用侧栏导航那套（`--accent-subtle` 底 + `--accent` 字 + `--accent-border` 边），
高度由 token 推出（3 + 32 + 2 = 40，与标准控件等高），`width: fit-content` 避免被 grid 父级拉满整行。
插件中心的两个页签、内容中心的三个页签、GitHub 热门的时间窗口（今日/本周/本月）都用它，全应用只有一种「当前选中」画法。
**实测**：选中项 `h: 32`，深色下 `color: rgb(56,189,248)` / `bg: rgb(14,42,58)` / `border: rgb(29,95,125)`；
页签容器宽 256px（主区 1064px），不再拉满；两套主题下对比度不合格 0 处、点击目标不合格 0 处。

# 第三轮：配色「更清爽」与三处版面重做

用户反馈：浅色下蓝色与绿色偏深、整体「有点脏」，深色也希望一起优化；另外工具管理页信息与间距要重做、
网关页的待应用行不要卡片、内容中心并入「扩展」组、页名改叫「网关」。逐条记录。

## C1 配色：能动的空间比看起来窄

判据有两条，而且必须**同时**满足：

1. 文字过 WCAG AA（4.5:1；`--status-*-dot` 这类非文本 3:1）；
2. `--accent` 既是**底**（白字压在上面）又是**字**（压在自己的淡底上）——两个方向都要 4.5。

第 2 条把亮度夹进一个很窄的区间：「再亮一点更好看」通常直接撞在第二关上
（实测：accent 亮到 `#0C78BD` 时，白字只剩 4.73 而压自己的淡底只有 4.29）。

于是这一轮真正的杠杆不是把蓝调亮，而是**把淡底调透**，让蓝有变亮的余量：

| 改动 | 从 → 到 | 实测（浅色，按 alpha 合成后算） |
| --- | --- | --- |
| 蓝更亮 | `#0A6FB0` → `#0B74B8` | 白字压按钮 4.99 / 压白卡 4.99 / 压淡底 4.62 |
| 淡底更透 | `#DCEFFB` → `#ECF8FF` | 撑住了上面那条 4.62；旧淡底配新蓝只有 4.23（不合格） |
| 描边更轻 | `#7DB9DD` → `#A3D3F0` | 装饰性描边，不参与 AA 判定 |
| 绿换冷绿 | `#15803D` → `#047857` | 压白卡 5.48 / 压浅底 4.95 |
| 状态点更亮更干净 | `#16A34A` → `#059669` | 压白卡 3.77 / 压选中底 3.14（门槛 3） |
| 成功浅底转冷 | `#E8F8EE` → `#E6F7F1` | 与冷绿同色族 |

深色这一轮只动两处：**灰阶整体转冷一档**（原值带一点暖，配天蓝显脏），
以及强调色淡底/描边提彩度（`#0E2A3A` → `#0D3247`、`#1D5F7D` → `#2A7FA8`）。
灰阶只挪色相不挪亮度，所以文字对比度不变（弱文字压卡片 5.43、压浮起层 4.93）。

**复核口径**：用 `body` 而不是 `main`。底栏的「网关运行中」在 `main` 之外，
只用 `main` 口径根本量不到用户点名的那个绿（2026-09-20 那轮审计也记过这个坑）。

## C2 工具管理页重做

原来的问题：两张卡（摘要 + 列表）之间空一大截、列表卡没有标题、每行一个徽章 + 时间但**看不出这个工具是什么**，
以及「这页到底干嘛的」没写清楚。

改成一张卡：标题与计数 → 搜索 → **可折叠的状态词典** → 列表 → 页脚说明。每行现在是：
展开箭头 / **单字底纹**（32×32）/ 名称 + 分类 / **路径 · 版本**（等宽、可截断）/ 状态徽章 / 探测时间。
行高实测 60px，展开详情里保留探针原文、配置位置、技能目录、复制路径与文档链接。

**不发厂商 logo**，理由是实测可行的三条都不成立：第三方商标随包分发涉及许可与版本更新；
运行时抓 favicon 会把「你装了哪些工具」泄露给外部站点，离线时整页没有图形；
而应用里**已经有**同一套做法（供应商列表用首字底纹）。所以沿用单字底纹 + 分类文字标签，
零外部依赖、零网络请求。

状态词典回答的正是最容易误读的一对：`已安装`（探针过了）vs `未验证`（探针没过，需要人看一眼）。

## C3 网关页：待应用行改平铺 + 页名

- 行改成 **不是卡片**：`background: transparent`、`border-bottom: 1px`，实测 `position: static`、
  与下方两栏间距 16px（修前那两个块是贴住的）。
- `nav.providers` 与页名改为 **网关**。注意：底栏的「网关运行中 · 127.0.0.1:18765」指的是**本机代理进程**，
  与这一页管的**上游供应商/模型**不是同一件事——同一个词有两层含义，已在
  [页面与流程](../design/04-pages-and-flows.md) 里写明，界面文案要避免把两者混在一句里。
- 概览页自己那条 `applyBar` 顺手一起改平：它原来也是 `position: sticky; bottom: 0` + 卡片，
  实测与上面那张卡片**垂直重叠 6px**。同一个东西在同一天里有两套长相，不如一起收掉。

## C4 侧栏顺序

按用户要求：内容中心并入「扩展」组，顺序为 内容中心 → 工具管理 → 插件中心；「诊断」组不变。
组标题仍是 `aria-hidden`、不可点、不进 Tab 顺序。

## 本轮的验证方式

- 颜色：先用脚本按 alpha 合成算比值选值（候选逐个列出比值），改完再用 `in-page-audit.js` 在真机浏览器复核；
  两套主题各自**冷启动**（`?theme=light|dark`），不在热切换后的页面上量。
- 版面：`getBoundingClientRect` 量与截图两种手段都用上了（本轮浏览器面板恢复正常渲染）。
