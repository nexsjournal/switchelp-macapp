# 工具栏「测试全部」与内置工具声明的版面审计（2026-09-22）

针对本轮四处改动里**动了界面**的两处做的符合性复测：

1. 模型列表工具栏新增的「测试全部」按钮（模型目录页与供应商详情里的嵌入版都看）；
2. 模型能力里新增的「上游内置工具」勾选单元格（整页编辑器与添加模型弹窗）。

工具：`scripts/in-page-audit.js`（作为字符串交给 `playwright.evaluate`）；夹具 `visual.html`；
主题用 `?theme=` **冷启动**量（热切主题后按钮底色仍是旧主题的，读数不可信，见
[设计规范符合性审计](../development/04-design-conformance.md)）。

## 1. 第一版的问题（已修）

| # | 现象 | 实测/依据 | 修法 |
| --- | --- | --- | --- |
| 1 | 「测试全部」嵌进供应商详情时变成一条横贯整栏的宽带子 | 那个工具栏是单列 grid（`.toolbarEmbedded`），子元素默认拉伸：实测按钮 **616 × 40**，而同类按钮是 114 × 40 | 给按钮自己的类加 `justify-self: start; width: fit-content`；复测 **114 × 40** |

## 2. 复测数字（修复后）

| 表面 | 主题 | overlap | overflow | clipped | 对比度不合格 | 点击目标不合格 | 紧贴 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 网关页 `main`（含「测试全部」） | 浅色 | 0 | 0 | 0 | 0 | 0 | 0 |
| 网关页 `main` | 深色 | 0 | 0 | 0 | 0 | 0 | 0 |
| 网关页 `main`（960×640） | 浅色 | 0 | 1（表格，见下） | 0 | 0 | 0 | 0 |
| 模型编辑器 `main`（含新单元格） | 深色 | 0 | 0 | 0 | 0 | 0 | 0 |
| 模型编辑器 `main` | 浅色 | 0 | 0 | 0 | 0 | 0 | 0 |
| 添加模型弹窗 `[role=dialog]`（高级配置展开） | 深色 | 0 | 0 | 0 | 0 | 0 | 0 |

- **「测试全部」按钮**：114 × 40（标准控件高 40），与搜索框、筛选行左对齐（`x` 同为 597）；
  嵌进详情时在 616 宽的工具栏里仍是 114 宽，不再拉伸。图标 + 文字，accessible name = 「测试全部」。
- **模型能力那一行**：三个单元格同为 32 高、间隔 8px（`函数工具` 108、`并行工具` 108、
  `上游内置工具` 136，x = 57 / 173 / 289，与上一行「输入类型」的 8px 节奏一致）。
- **智能配置那句提示**（弹窗）：实测文本「长度留空时按 1,000,000 / 128,000 补齐；最大输出不会
  达到窗口的一半。」——两个数字来自当前填写的窗口，不是写死的常量。
- **最小窗口 960×640**：无横向滚动（`scrollWidth = clientWidth = 960`），侧栏按规范收窄到
  **184px**。
- **键盘与语义**：无正 `tabindex`；每页恰好一个 `h1`；表头全部带 `scope="col"`；
  纯图标按钮缺名 0 个。

**窄窗那 1 处 `overflow` 是表格**（`table` 超出 `.tableWrap` 83px）。`.tableWrap` 就是
`overflow-x: auto` 的横向滚动容器，1280 宽时该问题为 0——它是 2026-09-20 审计已登记的
「窄窗表格不折叠」（§9.1/§9.2），与本次改动无关。

## 3. 功能实跑（不是只看渲染）

在夹具上点一次「测试全部」（两个模型）：

- 两行「连接」列都从 `未测试` 变成 `正常`；
- 右下角 Toast：「2 个正常 · 0 个失败 · 0 个缺 Key 未测」；
- 按钮在跑的过程中显示 `测试中 n/N`，跑完回到「测试全部」。

夹具的 `startProbe` 是合成结果，所以这里证明的是**界面把每个模型都测了、并逐行写回结论**；
真实探测链路由 `ModelsPage.test.tsx`（批量、跳过、汇总）与核心的 `probes` 用例覆盖。

## 4. 未覆盖

- 供应商弹窗里的嵌入版「测试全部」只量了几何（同一张表、同一个按钮类），未在夹具里点过——
  夹具的 `saveModel` / `listCredentials` 是写死的，点下去只会得到同一份合成结论。
- 真实的上游 400（`web_search` 不被支持）无法在夹具里复现：那是网关对真实上游的行为，
  由 `crates/switch-core` 的单元测试与端到端用例覆盖，不由界面审计覆盖。
