# 视觉基础与设计系统

## 1. 设计方向

关键词：深色、安静、明确、操作密度适中。以 `referimg/split-01.jpg`、`split-02.jpg`、`split-09.jpg` 的黑灰卡片和白色主按钮为主要参考，不复制品牌标识。页面第一眼必须回答“当前连接是否可用、用哪个模型、有没有未应用修改”。

不用营销大标题、渐变大背景、彩色统计卡片或无意义装饰。状态色只解释状态；供应商品牌色只出现在小图标，不扩散成整个页面主题。

以下 token 是本项目设计值，不是从 JPEG 精确取色的结果。

### 颜色为什么是这几个值（2026-09-21 一轮「更清爽」的调整）

> 这一节记的是当轮的判断与实测，其中的**强调色取值已被下一轮的青绿取代**（见下文
> 「第二轮：强调色由天蓝换成青绿」）。判据与方法仍然有效，取色时以 §2 的表格为准。

判据只有两条，但必须**同时**满足，所以能动的空间很窄：

1. 文字必须过 WCAG AA：正文类文字 4.5:1；`--status-*-dot` 这类非文本元素 3:1。
2. `--accent` 既是**底**（白字压在上面）又是**字**（压在自己的淡底上）。两个方向都要 4.5，
   于是它的亮度被夹在一个很窄的区间里——「再亮一点更好看」通常直接撞在第二关上。

实测下来这一轮改了三件事：

| 改动 | 从 → 到 | 实测（浅色） |
| --- | --- | --- |
| 蓝更亮更清爽 | `#0A6FB0` → `#0B74B8` | 白字压按钮 4.99、压白卡 4.99、压自己的淡底 4.62 |
| 淡底更透（这一步才是「不发灰」的关键） | `#DCEFFB` → `#ECF8FF` | 上面那条 4.62 就是它撑出来的；旧淡底配新蓝只有 4.23（不合格） |
| 绿换成冷绿 | `#15803D` → `#047857` | 压白卡 5.48、压浅底 4.95；状态点 `#16A34A` → `#059669`（压白 3.77，压选中底 3.14） |

深色这一轮只动了两处：**灰阶整体转冷一档**（原来带一点暖，配天蓝显脏），
以及强调色淡底/描边提彩度（`#0E2A3A` → `#0D3247`、`#1D5F7D` → `#2A7FA8`）。
灰阶只挪色相不挪亮度，所以文字对比度不变（弱文字压卡片 5.43、压浮起层 4.93）。

**不许凭感觉报数字**：以上每一个比值都由脚本按 alpha 合成后的真实底色算出，并用
`scripts/in-page-audit.js` 在真机浏览器里复核过（`body` 口径，包含底栏——
底栏的「网关运行中」是用户点名的那个绿，它在 `main` 之外，只用 `main` 口径量不到）。

### 2026-09-21 第二轮：强调色由天蓝换成青绿

用户原话：蓝色「太常规、太普通……总感觉不是那么专业，就像一个假的 App、一个工具」，要求换成青绿或橙色。选青绿不选橙色的理由：灰阶本身带一点冷蓝相（见上），暖色压上去显脏；青绿既不是「另一个默认蓝」，又仍然在冷色一侧。

| 主题 | `accent` | `action.primary` 上的字 | 强调色当字（压淡底 / 压侧栏） |
| --- | --- | --- | --- |
| 深色 | `#2DD4BF` | `#04211D` → **9.09** | 压 `#0C3A33` **6.76**、压侧栏 **10.30** |
| 浅色 | `#0F766E` | `#FFFFFF` → **5.47** | 压 `#E3F5F1` **4.85**、压侧栏 **4.77** |

浅色为什么不能再亮一档：`--accent` 同时是底（白字压在上面）又是字（压在 `accent.subtle` 上），
两个方向都要 4.5。`#0F766E` 已是「再亮一档就掉线」的位置。这几个比值都是在冷启动的
`?theme=light` 页面上量的（热切主题后量到的按钮底色是旧主题的，见 [验收](../development/02-testing-and-release.md)）。

同轮还有两处连带调整，都是为了不让「强调色」和「状态色」在同一个界面上像同一种颜色：

1. **成功绿由薄荷换纯绿**（深色 `#6EE7B7` → `#4ADE80`）。薄荷与青绿只差十几度色相，
   「已加载」的绿点和侧栏当前的青绿项会像同一个颜色。实测新值压卡片 10.21、压自己的淡底 8.79。
2. **浅色成功淡底偏绿**（`#E6F7F1` → `#E9F8EE`）。旧值与新的 `accent.subtle` 几乎同色，
   两种「淡底」就分不出来了；实测文字压新值 4.99。

`--status-info` 仍是蓝：语义色只有四个，且**状态不借强调色表达**（见下）。

### 表单描边分两档（2026-09-21，静息档当天调暗过一次）

用户原话：下拉框「未选择的默认样式的边框有点太明显了……全局都过下，统一下稍微弱化一些」。
从前静息态直接用 `border.control`（`#777783`），一页里六七个控件并排时边框连成一片。现在：

| 状态 | token | 深色实测（压输入底 / 卡片 / 浮起层） | 浅色实测（压白 / 画布 / 侧栏） |
| --- | --- | --- | --- |
| 静息 | `border.field` | `#50505C` → 2.38 / 2.24 / 2.03 | `#AAAAB2` → 2.31 / 2.14 / 2.01 |
| 悬停 | `border.control` | `#777783` → 4.27 | 4.42 |

**静息档是有意低于 3:1 的例外，登记在案。** 第一版取的是 `#6A6A76` / `#86868F`，
取值上限由验收规则「需要识别的控件边界 3:1」定死（深色压浮起层只剩 3.03，再暗一档就不合格）。
用户第二次仍说「太明显」，在给出上述实测数字与三条替代方案（保持 / 取消描边改用底色区分 /
0.5px 发丝线）之后，用户明确选择「再暗一档，接受低于 3:1」——所以现在这一档不满足 3:1，
**这是产品决定，不是回归**。审计时按例外处理，不要报成不合格项；要改回来只需动
`--border-field` 一个值。

代价最大的两处，将来要复查时从这里看：
- 浅色主题的输入框是白底压白卡片，边界只由这条描边表达；
- 勾选框未选中时就是「一个方框」，那是 WCAG 非文本对比最典型的场景（选中后填 `text.primary`，
  状态本身仍然清楚）。两处都仍清晰可见（2.0–2.3 远高于「看不见」），但确实不再满足 AA 的
  非文本对比要求。

同批统一：页面里自己画的「搜索框 / 内联输入框」（工具管理、插件中心、内容中心、**供应商页**）
从 `border.subtle` / `border.control` 换成 `border.field`——它们从前比全局控件还弱或还强一档，
同一页里两种控件两种边框。判据只有一条：**静息态一律 `border.field`，`border.control` 只用于悬停**
（以及语义色点、未选中状态点的填充）。

禁用态降低强调而非全部 opacity 降到不可读；禁用原因有正常对比度文字。正文对比度、控件边界和焦点至少按 [验收](../development/02-testing-and-release.md) 检查，不仅检查色卡值。

### 强调色的使用范围

灰阶体系里“可点、已选、当前在哪”三种状态没有颜色支撑时几乎看不出来，因此引入**同一个**强调色，只用在需要吸引注意的位置：

| 用在 | 不用在 |
| --- | --- |
| 主按钮（每个局部区域唯一一个） | 次要按钮：保持灰底，避免出现两个主按钮 |
| 侧栏当前导航项（淡底 + 强调色文字 + 强调色描边） | 所有导航项：其余保持灰阶 |
| 链接文字 | 正文里的强调：用字重而不是颜色 |
| 焦点环 | 常态描边 |
| 选中行、批量操作条、待应用栏 | 卡片边框 |
| 生效预览的“落在哪里”标签 | 状态徽标：状态有各自的语义色 |

语义色（成功 / 警告 / 危险 / 提示）与强调色是两套：**状态不借强调色表达**，强调色也不承担状态含义。两套主题里变量名完全一致，组件不写 `data-theme` 分支，避免两套样式各自漂移。

### 主题切换

三档偏好：**暗色 / 亮色 / 跟随系统**。`system` 在应用层解析成具体的 dark 或 light 再写入 `data-theme`，CSS 只认最终值；解析结果同时写入 `color-scheme`，让 `select`、滚动条、复选框这些原生控件跟随主题，而不是在亮色页面里渲染出深色下拉。

实现要点（对应 `src/theme.ts`）：首帧之前就把主题写到根元素，否则会先闪一下默认底色；偏好存 `localStorage`（界面偏好，不是秘密，不参与配置事务）；存储不可用时回落到暗色并照常渲染；偏好为 `system` 时监听系统变化即时切换。

亮色不是深色反相：反相会让卡片描边过重、语义色在白底上对比不足，所以另取一套灰阶与更深的语义色。

| 最小窗口 | 960 × 640；缩放时允许内容重排，不强制横向挤压 |

## 4. 空间与层级

间距使用 4 / 8 / 12 / 16 / 24 / 32 / 48。4 用于图标与短状态，8 用于标签与输入，16 用于相关字段，24 用于分组，32 用于页面区块。禁止同层卡片随意使用 17 / 23 / 29 等间距。

**卡片的四边内边距必须相等**（`--card-padding`，24 px）。曾经只有内容中心与插件中心的卡片写成 `20px 24px`，
于是卡片里第一行内容「距顶 21、距左 25」——单看每一处都不刺眼，并排就在一条斜线上（用户原话：
「新闻信息距上面的间距和距左边的间距好像不太一样，一眼就能看出来」）。列表行同理：行自身左右也要留
与上下同阶的内边距，否则「距卡片顶 38、距卡片左 24」。**例外**：纯文本面板（说明条、探针原文）允许水平
多留一档（`12px 16px`），那是给多行文本的呼吸空间，不是节奏漂移——用之前确认属于这一类。

**「标签 + 控件」行：标签与控件里的文字对齐**，不是与控件方框顶部对齐。控件的文字在 40 px 高的方框里
垂直居中，标签默认贴顶，看上去就高了一截。做法是给标签加 `padding-top: (control-height − line-height)/2`
（见 `SettingsPage.module.css` 的 `.controlLabel`），也不要把标签与「控件 + 下方说明」整体居中——那样标签会
跑到说明旁边去。这是第三类允许的光学微调（前两类见下）。

这条规则以前只被「读」过、没被「量」过：全量审计量出 `gap: 10px` 37 处、`padding` 里的 14px 9 处，外加 6/9/20 等零散值——每一处单看都不刺眼，合起来就是页面节奏不齐。现在已全部收回阶内。**两个例外，用之前先确认属于哪一种：**

- **光学微调**（2 px，以及 `.tableWrap` / `.checkHit` 那对 `padding: 7px; margin: -7px`）：它们不是排版节奏，是让图形对齐、或让点击区不被滚动容器裁掉的补偿值。必须在代码里写明用途。
- **控件横向内边距**（按钮与输入框的 `padding: 0 16px`）：它属于控件尺寸的一部分，随 `--control-height` 定义在全局，不在各页自己写。

卡片标题的视觉上边距要与左边距一致，但文字行框上方自带半行距与字面上缘空隙，标题行里更高的按钮还会把标题居中带下去。两部分都不参与排版判断，因此卡片首行用 `--card-title-optical-trim`（4 px）上提、标题块贴行顶（`align-self: flex-start`）抵消；同页所有卡片共用这一个值，不再各写各的。

圆角：微标记 4、输入/按钮 8、导航 10、卡片 14、弹窗 16、胶囊 999。阴影只用于浮层：`0 12px 32px rgba(0,0,0,.28)`；卡片不靠多层阴影区分。

层级：page 0、sticky toolbar 10、apply bar 20、drawer 30、dialog 40、toast 50、tooltip 60。模态遮罩只压暗不模糊敏感字段，避免复杂 GPU 效果。

## 5. 动效

Hover 100 ms，Popover/Dialog 140–180 ms，抽屉 180 ms。优先 opacity/transform，不做弹簧大幅位移。网络进度用真实阶段，耗时未知时使用不定进度，不显示假的 99%。用户启用 reduced motion 时去掉位移和循环动画，保留状态文字。

保存中的按钮保持宽度，避免文字替换造成跳动。测试结果原位出现；不能每次测试都弹遮挡页面的对话框。首次加载 skeleton 保持最终布局，持续超过 2 s 出现“仍在读取”和取消/重试条件。

## 6. 品牌与资产规则

产品临时名称 Switchelp，副标题“Codex 配置管理”。应用图标另行设计：两条平行连接线与单一活动节点形成可识别切换意象；黑灰基底、白线、一个低面积冷青点。不得使用 CodexSplit 菱形标志或暗示 OpenAI 官方产品。

交付规格：矢量母版、1024 方形 PNG、macOS icns、Windows ico；托盘 16/20/24/32 单色版本，macOS 模板图标需适配系统深浅色。此轮仅写资产规格，不生成正式商标/图标成品。
