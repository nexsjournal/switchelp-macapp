# 图标、文字、字体与内容规范

## 1. 图标库决策

统一使用 Lucide outline。图标按模块静态导入、随应用离线打包；不从 CDN 动态下载，也不根据 endpoint 自动请求 favicon，避免启动时向第三方暴露供应商使用情况。Lucide 采用 ISC，少量源自 Feather 的图标另含 MIT；按实际安装包保留声明。[Lucide 许可证](https://lucide.dev/license)

Remix Icon 可作为备选，但同一版本不混用两套线宽体系。若改用 Remix，先固定版本与许可证并替换映射。[Remix Icon](https://remixicon.com/)

### 1.1 图案尺寸只有五档

上表的 18/16 是两档常见用法；完整规则是**五档**，其余值（11、13、15、17、19、22…）一律不收：

| 档位 | 尺寸 | 用在哪 |
| --- | --- | --- |
| 微型 | 12 | 套在 ≤22 px 的容器里：勾选框里的对勾、胶囊里的删除叉、步骤圆点里的对勾 |
| 行内 | 14 | 与 caption / label 文字同行的图标（提示条前缀、面包屑箭头、时间与单位旁） |
| 控件 | 16 | 按钮、表单行、列表行操作、字段标签 |
| 区域 | 18 | 侧栏导航、卡片与区域标题、32 px 方形图标按钮 |
| 展示 | 20 | 弹窗左侧的条目类型标识、品牌位 |
| 插图 | 26 / 28 | 空状态与冲突提示的插画级图形，随容器走，不参与上面的节奏 |

原文只写了两档，是这一轮审计量出「12 个页面里混排 8 种尺寸」之后补的：14/15/17/20 四种值交替出现，看起来「差不多」，并排就错位。**改尺寸前先回来对这张表。**

图标是弹性项时**必须**加 `flex-shrink: 0`：兄弟节点是一段长文案时，默认的 `flex-shrink: 1` 会把图标压成一条（实测出现过 8.91 × 16 的警告图标）。

装饰图标 `aria-hidden`，纯图标按钮必须有中文 accessible name 和 Tooltip；Tooltip 不能成为唯一错误说明。

### 1.2 同一个意思只留一个图形：勾选框的对勾

对勾是这一条的第一个实例，因为它是全项目出现次数最多的图形，也最容易漂成两种。
从前项目里同时存在**两个**对勾：组件里的能力单元格画的是 Lucide `Check`（圆头圆角），
而列表里的原生勾选框交给引擎画（macOS 上 18 px 的原生对勾是细折线、直角收尾）。
用户原话：「勾选的对号 icon 好像是直角的，和其他的这个 icon 也不一样……有能统一的就统一一下，
别一个意思搞了好多种图标」。

现在的规则：

- **方框与对勾都由 CSS 画**（`global.css` 的 `input[type='checkbox']`：外框 18 px、
  4 px 圆角、选中时填 `--text-primary`），对勾是 `--checkbox-tick` 这枚 data URI，
  `stroke-linecap: round`，与 Lucide 的线头一致。颜色必须跟着主题变，所以它是 token 而不是写死的 SVG。
- **组件不再自己画对勾**：`CheckCell` 只负责「带描边的单元格」这一层皮，
  于是整页模型编辑器、添加模型弹窗、诊断包范围、插件中心的安装目标、模型表格的批量选择
  共用同一个形状。新增多选时**不要**再画第二个对勾。
- 需要「已勾选但不可改」时用 `disabled` + 旁边一枚 `Lock`，不要换一套勾选样式。

同理适用于其它高频图形：同一动作（复制、打开路径、删除…）只有一个图标，见 §1 的映射表；
尺寸只有 §1.1 的五档。新加图形前先在这两张表里找一遍。

## 2. 供应商品牌图标

预设目录只引用可核实授权的本地品牌资源，并记录来源与版本；其余使用带字母/汉字的中性 Avatar，不临时抓网络 Logo。32 px 列表图标，40 px 详情图标，背景遵守统一圆角。自定义上传若开放，仅接受受控位图；SVG 要净化，不允许脚本或远程资源引用。

品牌名用于识别服务商，不表示合作、认证或可用性。供应商展示名由用户决定，原始厂商可作为次级字段，不用品牌推断 API 协议。

## 3. 字体栈

UI：`Inter, -apple-system, BlinkMacSystemFont, "Segoe UI Variable", "Segoe UI", "PingFang SC", "Microsoft YaHei UI", sans-serif`。Inter 如实际分发，内置 WOFF2 并附许可证；中文依赖平台字体，不在线加载 Google Fonts。macOS 系统字体仅使用系统安装版，不复制 SF 字体到 Windows。

代码与数据：`"SFMono-Regular", Consolas, "Liberation Mono", monospace`。模型 ID、URL、路径、Token 和延迟使用等宽或 tabular-nums；中文说明仍用 UI 字体。

| 字阶 | 字号/行高 | 字重 | 使用 |
| --- | --- | --- | --- |
| 页面标题 | 28 / 36 | 650 或 600 | 每页一个 H1 |
| 区域标题 | 18 / 26 | 600 | 模块 |
| 卡片标题 | 16 / 24 | 600 | 供应商/模型名 |
| 正文 | 14 / 22 | 400 | 说明、常规内容 |
| 控件文本 | 14 / 20 | 500 | 输入、按钮、选择 |
| 字段标签 | 13 / 20 | 500 | 必须常显 |
| 辅助说明 | 12 / 18 | 400 | 来源、时间、单位 |
| 数值强调 | 24 / 32 | 600 | 少量状态数据，不做首页 KPI 墙 |
| 代码字段 | 12–13 / 20 | 400 | 路径、ID、diff |

正文不小于 12 px；中英文之间适当空格，名称不自动标题化。多行错误完整可见，不用省略号隐藏恢复步骤。模型 ID 支持复制并保留原始字符。

## 4. 文案规则

中文优先，API Key、Base URL、Token、Responses 等技术名词保留。第一次出现可附短解释；后续统一术语。一个按钮只代表一个可预测动作；只有确实会重启时才写“重启 Codex”。

禁止含混用语：“一键修复全部”“智能校准中”“激活成功”“无损万能兼容”“全部能力支持”。推荐表达结果、范围和下一步。

| 场景 | 标准文案 |
| --- | --- |
| 草稿保存 | 已保存，尚未应用到 Codex。 |
| Key 热切换 | 后续新请求使用「工作 Key」。进行中的请求保持原配置。 |
| 目录已提交 | 模型目录已更新。Codex 重新加载后可见。 |
| 宿主不可观测 | 配置已提交，尚未确认当前 Codex 窗口已加载。 |
| 完整成功 | Codex 已加载 3 个模型。最近一次路由验证通过。 |
| 测试只是文本成功 | 文本请求通过。工具调用和图片输入尚未验证。 |
| 模型发现不支持 | 此接口未提供模型列表。可手动填写模型 ID。 |
| 能力未知 | 未获取到该能力信息。可填写服务商文档中的值。 |
| 输出参数被限制 | 本次输出上限为 8,192 Token，受模型策略限制。 |
| 文件不能原生传入 | 当前 Codex 接入方式不能原生发送 PDF。 |
| URL 改动 | 服务地址已更改，需要重新测试模型权限。 |
| 冲突 | 配置在预览后被修改。重新比较后再应用。 |
| 失败恢复 | 应用未完成，已恢复上次配置。 |
| 恢复冲突 | 检测到外部修改，已保留当前文件。请选择要恢复的字段。 |
| 退出依赖 | 退出后，使用本地网关的第三方模型将暂时不可用。 |

### 4.1 什么叫「写给开发者看」——负面清单（2026-09-21 全量过了一遍）

这一轮把 `src/locales/` 里约 1200 条文案按「这是写给用户，还是写给读代码的人」重过了一遍，
改掉 60 多处。判据不是「够不够通俗」，而是**这句话能不能拿来做事**。五种反复出现的毛病：

| 毛病 | 真实例子（改前） | 改后 |
| --- | --- | --- |
| 内部标识、协议字段名直接上界面 | `reasoning.effort.v1：档位随协议原样发出（Responses 写 reasoning.effort…），只记为损失` | `勾选的档位会按接口原样发送；没有勾选的档位不会发送。` |
| 解释产品自己怎么实现 | `映射写在网关的适配器里并且已经版本化，界面上改不了` | `这一项由本机网关固定处理，不能在这里修改。` |
| 把路线图写进功能说明 | `Anthropic 的 Messages 格式还没实现`、`装配完整`、`尚未实现` | `暂不支持 Anthropic 的 Messages 格式`、`目前只在 macOS 上可用` |
| 一件事说两遍 | 上下文构成在「字段提示 / ⓘ / 区块说明」里出现三次；`事务` 与 `操作` 混用 | 一处说清，其余删掉 |
| 错误只说发生了什么 | `内部错误。`、`数据不满足存储约束。` | `本工具内部出错，请重试；仍然失败可到日志页导出诊断包。` |

**保留不动的**：必须保留的技术名词（API Key、Base URL、Token、Responses、Chat Completions、`config.toml`、
CODEX_HOME、bridge、RSS、GitHub），以及一切精确的事实与上限——精确不是 AI 味，含糊才是。
`# >>> xxx managed >>>` 这类**用户真的要照着删**的原文标记也要原样给出。

**几个词的统一口径**：宿主 → `Codex`；事务 → 「这次应用 / 这次操作」；后端 → 「本工具」；
受管字段 → 「本工具管理的字段」；门禁 → 「验证」。

## 5. 时间、数字和来源

Token 使用千分位精确值，可附简写 `128k`；永远显示单位，避免 128 被误当 128k。延迟以 ms / s 自动切换；`—` 表示未知，0 仅用于实测零值。最近检测显示相对时间，hover/详情显示含时区的绝对时间。

能力来源标签采用“服务商返回 / 官方文档 / 用户填写 / 测试确认 / 未知”。测试确认附具体项目和时间，不用一个绿勾把全部能力都认证。配置路径默认可见脱敏形式，详情允许本机完整路径，导出时自动替换用户目录。

## 6. 国际化

所有 UI 文案进入 locale key，不在 Rust 错误中拼最终中文。预留英文，不在多个卡片重复放语言按钮；设置页统一语言入口。长英文、CJK、RTL 字符模型 ID、Unicode 组合字符均需处理，ID 显示采用隔离方向避免混淆。
