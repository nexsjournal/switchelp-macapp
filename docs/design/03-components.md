# 组件与业务模块规范

本文件定义组件视觉、数据和行为。视觉 token 见 [基础系统](01-foundations.md)，页面组合见 [页面规范](04-pages-and-flows.md)。所有组件必须覆盖 default、hover、focus-visible、disabled、loading、error 中适用的状态。

## 1. 基础组件

| 组件 | 规格与变体 | 行为及验收 |
| --- | --- | --- |
| Button | primary 白底黑字；secondary 灰底边框；ghost；danger；32/40/44 高 | loading 保持宽度；禁用给出原因；Enter/Space；危险操作不能靠红色独立说明 |
| IconButton | 32/40 方形，16/18 图标 | accessible name 必填；Tooltip 延迟约 400 ms；不吞焦点环 |
| TextField | 标签在上，40 高，8 圆角，静息 `border.field`、悬停 `border.control`，辅助文本在下 | placeholder 不是标签；blur 校验，保存时聚焦首错；输入过程不反复弹 toast |
| SecretField | 密码输入，显隐按钮，保存后只显示 mask | 编辑旧 Key 使用“替换”动作，不把 mask 当原值提交 |
| NumberField | 单位后缀 Token/ms；可选自动开关 | null 与 0 分开；不随鼠标滚轮误改；支持粘贴千分位后明确解析 |
| URLField | 等宽，协议/路径即时解析提示 | 仅提出修正，不自动提交更改地址；错误明确到协议或路径 |
| Select/Combobox | 40 高，描边同 TextField（静息弱一档），搜索、分组、键盘定位 | popup 最大高 320；当前选中可见；未知值显示已失效，不自动选第一项 |
| Checkbox | 18 图形；方框与对勾由 CSS 自绘（`--checkbox-tick`，圆头圆角，与 Lucide 同一套线头），方框描边同 TextField；点击区由**外层**（`.check-label` 整行 / 表格的点击层）撑到 32 | 三态用于部分选中；批量操作清晰标明作用范围。不要用「透明边框 + 负外边距」把方框自己撑大：那会把标签文字吸到框上、方框戳出内容线。也不要用 `accent-color` 交给引擎画：那会在同一个界面里造出第二种对勾（见 [图标规范 §1.2](02-icons-type-and-copy.md)） |
| Switch | 36×20，标签说明 | 只表示立即可理解的二态；复杂接入不得只用一个 Switch 隐式重启 |
| Badge | 12 px，最小高 22，点/图标+文字 | 不是按钮除非有明确交互；颜色不作为唯一编码 |
| Tabs | 36 高，底边/背景选中 | 左右键，独立 tabpanel；不嵌套三层 |
| Tooltip | 12 px，最大宽 280 | 不放必填说明、错误或长步骤 |
| Dialog | 480/640/800 宽，16 圆角 | 标题/说明/焦点陷阱/返回焦点；取消安全；不可丢弃正在提交事务 |
| Drawer | 560–720，右侧进入 | 背后保留上下文；简单详情；复杂模型编辑跳专页 |
| Toast | 右下角悬浮，最多 3 条；成功 5 s、信息 7 s、**失败不自动消失** | **一次性反馈的唯一出口**：`ToastHost` 挂在应用壳最外层，弹窗与常规界面共用同一个位置（挂在 body 上渲染，不受容器 `overflow` 影响）。判别规则：**动作的结果**（已保存、已添加、连接成功/失败、批量完成）走 Toast；**页面状态**（读不到数据、网关未启动、待应用数量）留在页面内联条里。表单校验错误归字段自己（「错误显示在相关字段下」） |
| EmptyState | 小图标、标题、一句解释、一个动作 | 不用大插画；区分未创建/筛选无结果/读取失败 |
| DiffViewer | 字段级摘要默认，原始 TOML diff 可展开 | 秘密遮罩，正负符号+颜色；显示目标文件和修改原因 |
| ProgressSteps | 纵向阶段，当前状态+耗时 | 真实进度，失败停在具体步骤；不伪造百分比 |

## 1.1 弹窗的保存语义：保存成功就关

**2026-09-21 改**：供应商弹窗（ProviderForm）点「保存」成功后**关闭弹窗**，只留一条确认。
从前是留在弹窗里就地变成这家供应商的编辑态（理由是「接着加 Key、获取模型」），但用户的实际读法是
「点了保存什么都没发生」——只有一条 toast，弹窗纹丝不动（原话：「给人的感觉就以为没有操作成功一样」）。
加 Key、获取可用模型、改名这些**就地动作**各自保存、各自报 toast、都不关弹窗，所以关掉它不会丢掉
任何已完成的事；要接着配置，从列表里再打开这家供应商即可。

这条可以推广：**「保存」代表这件事办完了**；需要连续操作的弹窗里，连续动作用就地按钮表达，
不要靠「不关弹窗」来暗示。

## 2. ProviderRow / ProviderCard

信息顺序：32 px 图标 → 名称 → endpoint host/path → 模型数量/Key 数量 → 最近测试状态 → 管理入口。选中用于导航，行内测试是独立按钮，不能点击 Key 标签触发应用。

列表显示“已保存”与“可连接”两个不同事实；只有未配置 Key 时出现“添加 Key”。悬浮不改变布局。长名称单行省略，详情完整；URL tooltip 不含 query 秘密。

可选状态：未配置、草稿、已保存未测试、测试中、可连接、部分模型失败、凭据不可用、已停用。供应商整体红色不能隐藏其他仍可用的模型。

## 3. CredentialRow

字段：Key 备注、固定掩码/尾号、当前新请求标记、检测结果与时间、更多菜单。更多菜单包含检测、设为新请求使用、替换、禁用、删除。默认固定策略显示在列表标题旁；P1 才出现 failover 选项。

当仍被续接绑定时，删除按钮进入“停用并等待释放”计划；文案说明依赖请求数量，不能暴露会话正文。Keychain 记录缺失与 API 401 是两个状态，给不同修复动作。

新增 Key 用内嵌表单而非叠加弹窗：备注 + SecretField + 保存；不同时保存供应商其余未提交变更，除非主按钮清楚写“保存供应商及 Key”。

## 4. ModelRow / ModelTable

列顺序：选择框、显示名/上游 ID、供应商、协议、能力摘要、检测状态、Codex 状态、操作。能力摘要最多 3 项加“+N”；完整能力在详情，避免首屏出现十多个徽章。

模型业务状态与宿主状态分列：业务“已保存/停用”，宿主“待应用/已加载/加载未确认”。测试通过不替换宿主状态。模型在失败状态仍可进入编辑，不能被筛选默认隐藏。

多选可批量测试、纳入/移出目录；移除目录不等于删除供应商模型记录。跨供应商同名模型显示供应商后缀，保证区分。

## 5. CapabilityEditor

两处共用（整页模型编辑器、添加模型弹窗的「高级配置」）：

1. **长度**：上下文窗口、最大输出；压缩阈值放「高级配置」。
2. **能力**：输入类型（文本、图片、音频、视频、PDF）与工具（函数调用、并行调用）都是**勾选单元格**。
3. **思考**：上面一行是「支持的档位」（勾选单元格），下面一行是「默认档位」（只在勾了至少一项时出现，单选）。

规则：

- **勾选而不是三态下拉**：勾＝声明支持，取消＝声明不支持，**没点过的项保持「未确认」并在保存时原样写回**。核心的能力是三态（支持 / 不支持 / 未知），未知不能被渲染成不支持——把未知写成不支持会通过交集原则把这个能力从 Codex 目录里灭掉。所以界面上不摆一个「未知」选项，让人以为必须逐项做决定。
- **文本**是链路底线：勾着、锁着、点不动。**PDF / 视频**当前链路发不出去：可见、灰态、点不动（需求 R22），勾了也不会出现在原生能力里。
- **档位从集合里勾，不是自由文本**（2026-09-21 改）。集合是 `minimal / low / medium / high / xhigh / max / ultra`（中文标签：极简 / 低 / 中 / 高 / 超高 / 最高 / 极致），取值来自本机 ChatGPT.app 里那份 codex 二进制的 `ReasoningEffort` 枚举——档位会被投影进 Codex 的模型目录，写它不认识的值轻则这一档在宿主里没有标签，重则整个目录条目被拒。集合定义在 `src/features/models/policy.ts` 的 `REASONING_LEVEL_PRESETS`。
  - `none` 故意不在表里：核心适配器的注释里记着真实故障——宿主在没有档位可选时会送一个 `none`，转发出去上游直接拒绝（moonshot 返回 400）。把它摆成「最低档」会诱导用户声明一个大概率被上游拒的值。
  - **已保存但不在集合里的档位（老数据、上游自定义值）原样显示在末尾、可取消勾选**，绝不因为「界面上没这一项」被悄悄丢掉。
  - 落进策略的集合按档位从低到高排序，不按点击顺序；默认档位是已经定下的那个，增删别的档位不会把它改掉，它被取消时才落回剩下最低的一档。一个都不勾＝不声明思考，不向上游发送任何思考参数。
- **「这个值落在哪里」写在每个字段的「ⓘ」上**（进 Codex 目录 / 只影响网关请求 / 目录建议值 / 三层交集），不再单开一栏预览让人对照着读。档位的「ⓘ」还会写明「发送给上游的值就是 `reasoning.effort = <值>`」。
- 单元格宽度由内容决定，同一行里对齐；不再出现同一页有人两列、有人三列的混排。
- 「其他文件」（document）不出现在界面上：它既不能被投影到 Codex 目录，链路上也没有通路，摆出来只会让人以为勾了有用。

修改发现值显示「用户覆盖」，旁边可恢复来源值；刷新模型不覆盖。未知上下文可保存草稿，应用时集中提示需要填写。默认思考不能选择未声明档位。

## 6. ConnectionStatusPanel

固定五行：本地服务、服务商认证、模型调用、工具续接、Codex 加载。每行都有状态、时间、动作；加载未确认不能用“连接成功”统称。

折叠状态只显示最需要处理的一项和总体文案。例如“模型可用，等待 Codex 重新加载”；展开才显示技术端口、协议和版本。用户不应先理解 Bridge、egress、SSE 才能连接。

## 7. PendingApplyBar

**已实现（2026-09-21 改版）**：只在**网关页**出现，位置是页头下方的一行。

- **不吸底、不跨页常驻。** 早期版本是 `position: sticky` 常驻页面底部、出现在除 Codex 配置以外的每一页；
  实测问题有两个：一是每页都盖住视口底部一行内容（2026-09-20 审计已记为 P2），二是它容易被读成全局状态栏。
  入口该在用户配东西的那一页——用户正是在网关页配供应商与模型。
- **不是卡片**：只有一条底部分割线。做成卡片会和真正的卡片（供应商详情）抢层级，
  也会跟下面的两栏贴在一起显得像同一个块。
- 左侧说清事实：`N 个模型待应用 · 涉及 M 家供应商（名字）`，或配置已写完时的
  `已应用，等 Codex 确认加载`；右侧两个动作：「查看差异」切到 Codex 配置页看完整事务状态，
  主按钮按状态是「应用并重启 Codex」或「Codex 已经重启了」。
- 「应用并重启」走 **生成计划 → 差异确认 → 写入 → 重启宿主 → 结论**。确认那一步不省：
  写的是 Codex 自己的配置文件，而且会重启用户的 Codex。
- 重启完成后由本应用当场交回执（退出与启动都观察到才算）；观察不到时主按钮保持「Codex 已经重启了」，交给用户确认。

「有几个模型待确认加载」这个事实同时出现在顶栏胶囊、概览页与底栏，四处用同一句文案，改口径要四处一起改。

## 8. ApplyResult / RecoveryPanel

展示目标实例、修改摘要、实际完成阶段、未完成步骤、旧版本保留情况。成功时“打开 Codex”；等待状态“稍后重新加载”；失败时唯一推荐动作由 error.recoveryActions 决定。

字段冲突用三列“原配置 / 本工具写入 / 当前配置”，默认保留当前值；用户选择撤销具体字段后重新计划。不提供不解释范围的“强制修复”。

## 9. PresetSelector / TemplateCard

供应商预设只填公开 Endpoint 与协议建议，不预填真实 Key。模板包括名称、适用协议、来源日期、能力假设和将修改字段。应用模板前提供 merge/覆盖预览；未知项保持未知。

模型能力模板是起点，不是认证标章。模板名称用“文本工具模型（待验证）”，不写“全能模型”。

## 10. DiagnosticTimeline

每次测试一张可展开结果：时间、目标、阶段、耗时、失败原因、恢复动作。复制只复制脱敏诊断摘要。自动滚动仅在用户处于底部时启用；开始查看旧日志后停滚，显示“有 N 条新记录”。

日志页的**诊断包范围**（`gateway / apply / probe / discovery / credential`）是一次真正的多选，
用与其他多选同一套的勾选单元格（`CheckCell`）呈现，而不是「原生勾选框 + 一行文字」
（2026-09-21 改，用户点名要的就是「带个框框」的样式）。范围改变时已生成的预览作废，
避免「保存到本地」导出的包与预览清单不一致。

所有业务组件在组件预览中至少有空、加载、部分失败、全部失败、外部冲突和长文本实例。禁止只开发 happy path。
