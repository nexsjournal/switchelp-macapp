## 0. 一句话结论

社区把这类模型的用法收敛到两句大白话：**「在有限选项里选一个」和「按把握程度分流」**。
用户点名的这批内容里，真正值得搬进 Switchelp 的是六个能点着玩的界面：**模型擂台、闸门（按把握放行）、灵感雷达、规则工作台、出站体检、校准小游戏**；它们全部能挂在现有页面上，且用**本地开源 Laya（约 260 MB，首次下载，Apache-2.0）**就能跑，不需要 TypeSafe 账号。
同一批内容也给出了**四条"别这么用"**——最扎眼的一条是：**有人把决策模型插进 Codex 做"换便宜模型省钱"，实测反而多花 59%–184%**。

## 2. X 长文的两次实测与四次失败（**写产品前必读**）

### 2.1 四次失败——都是"塞进日常工具"死掉的

| 想干的事 | 结果 | 卡在哪 |
| --- | --- | --- |
| 给 Claude Code 装上下文压缩插件 | 装不上；勉强跑是"**无脑删**"，换成对什么都答 0 的假模型效果一样 | 为塞进 32K 上限把内容全砍了，模型只看到工具名和长度 |
| **给 Codex 做模型路由、省额度** | **反而多花 59%–184%**，每步多等 1–2 秒 | 中间代理把请求变重 2.5 倍，还弄丢了 cache |
| 给自己的稿子挑"AI 味" | 快又便宜，但 62 句里 **22 句误报**，净增价值约零 | 用户本来就逐句自审，它没多抓出一句 |
| 判断 40 个大视频哪些能删 | 判 **0 个**能删，纯规则能判出 7 个 | 看不到文件内容，只能凭文件名猜 |

作者自己的归因：①**看不到内容**（要准就得给内容，给内容就超上限）；②**订阅制杀死经济学**（判断本就包在月费里，边际成本是 0，再插一层只多一层毛病）；③**它只会判断不会干活**。结论：**"想拿它给自己提效的人走不通；把它当零件做进产品的人才有可能。"**

### 2.2 两轮实测——唯一值钱的用法是"按把握分流"

- **第一轮**：让 Jev 给 217 个 Jev 项目打分"今天能不能用" → 只有 **15 个**证据充分可用，其中 **14 个是框架接入**（pydantic-ai / LangChain / Vercel AI SDK），唯一应用是 `jev-ultrafast`。
- **第二轮**：**100 条中文资讯 × 3 题 = 300 个判断**，上海串行调用，人工先标好答案，对照一个便宜大模型：
  - **说"九成以上把握"的 255 个判断，一个没错**；阈值设 **0.80** 可自动放行 **89%** 的请求、只错 1 个；
  - 中位延迟 **约 0.7 秒**，最慢 1.5 秒；对照模型中位相近但**最慢 32 秒** → "**Jev 赢的不是快，是没有长尾**"；
  - 准确率 94.7% vs 93.0%、费用各约 $0.003 → **对上轻量模型，它不便宜也不更准**，多出来的只有"稳定的反应时间"和"每答带一个把握程度"。
- 作者的三步建议：列出"现在用大模型、但其实只要它返回一个选项"的调用 → 拿真实历史数据盲测，**重点看 70%–90% 那一档** → 过了就在大模型前加闸门，**从 0.90 阈值起步**。

> 对 Switchelp 的映射（【推测】）：我们恰好有"很多本来就只需要一个判断"的位置（该不该降级、这条资讯算不算干货、这段出站内容能不能发给这家供应商），而**路由/压缩这两件社区公认踩坑的事，恰好也是我们文档里已经标记"不要做"的**——两边独立得出了同一个结论。

## 3. OpenAI Decisions API（DevDay 2026，9-29）——同类品的第三条路

| 事实 | 档位 |
| --- | --- |
| DevDay 2026 发布 **Decisions API**：把"Luna 的智能"用于**用户定义、答案有限**的问题，做**实时分类、请求路由、选择 Agent 的下一步**；输入支持**文本或图片** | 【官方】 |
| 状态：**limited preview**，官方称"未来几天内扩大开放"；**未公布价格、限流、地区** | 【官方】 |
| 官方自己写明的边界：不适合"答案非有限集合/需要创造新方案"；**高影响场景（招募、授信、医疗、理赔、执法）需人工监督**；应保留"不确定/人工审查"出口；**选择≠授权**，执行层仍要校验权限；**有限答案不能消除提示注入** | 【官方】 |
| 同场还发布了 GPT-6.1 Sol（约为 Astra 标准 token 价的 1/5）、超高速（最高 8×/300 tok/s）、Codex Cloud、Codex CLI 焕新、代码审查、Codex Security Cloud、插件生态、MCP 事件驱动插件等 20+ 项 | 【官方】 |

**含义**（【推测】）：这个品类被主流坐实了，但它是**云端**的——"判断不出网"依然是本地 Laya 的差异化；同时它官方承认的边界（有限答案≠防注入、要保留人工出口）正好是我们设计里 already 写的规则（规则先短路、灰区才问、fail-open、不静默安装）。

## 4. 重新排序的功能清单：六个"好玩 + 能落地"的玩法

配套 Demo：**[docs/demo/jev-features-demo.html](../demo/jev-features-demo.html)**（每个都能点）。

| # | 玩法 | 落在 Switchelp | 一句话 | 为什么值得做 | 社区依据 |
| --- | --- | --- | --- | --- | --- |
| 1 | **模型擂台** | 概览 / 网关新增页签 | 同一个问题并排发给 2–4 个供应商，本地小模型当裁判，**按你自己的偏好**打分出榜 | 把"哪个模型好"从公开榜单变成"对你这份活儿谁更好"；天然可晒 | 公开榜单与私有 workload 脱节；社区同类"私有榜单"需求普遍 |
| 2 | **闸门（按把握分流）** | 网关（默认 shadow） | 把握够高直接放行，拿不准才转大模型；阈值滑块上能看见"省钱 ↔ 出错"的取舍 | **社区唯一有公开实测支撑的用法**（>0.90 档 255/255 全对；0.80 放行 89%、错 1） | X 长文两轮实测 |
| 3 | **灵感雷达** | 内容中心 | 每条资讯先过一遍本地判断（干货/标题党/情绪诱导/广告），按挑食度沉底，**只排序不删除** | 已有两万赞验证的同款玩法，做进桌面端且判断不出网 | 小红书两篇 + 作者的开源插件 |
| 4 | **训练你的小裁判** | 设置 → 决策服务 | 你纠错一条，它就多一条规则；一致度从 1/3 走到 3/3 | 把社区公认的**核心难点**（规则要写清楚、判错的写回规则）做成界面 | 小红书作者评论区原话 |
| 5 | **出站体检** | 网关（可关） | 发出去之前先看一遍：已知密钥/内网地址/客户名**正则硬挡**（真的跑），模糊情况才问本地模型 | 切供应商场景里的真实风险；比隐私政策好懂 | `jev-secret-guard` 同思路；本产品自己的"规则先行"原则 |
| 6 | **校准小游戏** | 设置 → 决策服务（自测的游戏化） | 和本地小裁判猜拳，它每局报把握，五局后看"把握 vs 实际" | 最好玩、最适合传播；顺手把"**置信度≠正确率**"教给用户 | 博弈论对战站（6 个游戏）+ 官方承认校准只到群体级 |

**次要但值得记一笔**：把本地决策服务以 `/v1/systemone` + MCP 暴露给 Codex（社区 15 个"真能用"的项目里 14 个是框架接入——**接口才是今天能用的形态**）；以及彩蛋类灵感（地铁跑酷、Jevton 小镇、找文件、切 PPT、多助手分配任务）可作为**推广素材**而不是功能。

## 5. 与既有文档的关系（两处立场更新）

1. **默认后端改为本地 Laya**（用户决定，2026-09-30）：开源 Laya 完全够用，**不依赖 TypeSafe 账号**；托管 Jev 降为可选项（BYO-Key），只保留"用户自己填了 Key 才出现"的位置。这修正了 [需求 01](../requirements/01-jev-feature-requirements.md) 与 [开发方案 05](../development/05-jev-integration-plan.md) 里"借道已有供应商为默认"的排序——**借道降为备选（在线兜底），本地 Laya 升为默认**。
2. **"闸门"与"路由"必须分开**：闸门（放行/转交）有实测支撑；路由（按轮次换模型）有 59%–184% 的反向实测。开发方案里的 `GatewayRoute` 用途保持"默认 shadow、不自动切换"，且**新增用途**：`Gate`（高把握放行）。
3. 不做清单增补：**不做**把决策模型塞进压缩/上下文裁剪（看不到内容就只会瞎判）；**不做**"AI 味检测"这类主观且误报高的判断；**不引用**没有许可证或 CC-BY-NC 的权重。
