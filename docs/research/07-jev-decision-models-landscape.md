## 0. 一句话结论

Jev 是 **TypeSafe AI 于 2026-09-15 发布的第一个「System One」决策模型**：发一个 `state` + 一组**类型化问题**（Noul 是/否、Choice 单选、Score 打分），拿回**带概率的结构化答案，不生成任何文本**；两周内长出一整片兼容生态（托管 API + 大量开源复刻）。**能用在 Switchelp 里，但正确姿势不是"上线一个 AI",而是"先计量、先记录、先规则"**：

- **最该先做的两件事都不需要任何模型**：用量页的离线成本洞察（P0-1）与上游错误归因的规则表（P0-4）；生态里唯一有公开 holdout 的收益（−19.8%/−29.9%/−41.5%）也来自**纯确定性裁剪**，不是决策模型【仓库/代码·自测，笔记 03】。
- **要真用模型，最省钱的路线是"借道用户已经配好的供应商"**（含免费档模型），其次才是本地 Laya（首次下载 ≈260 MB），最后才是托管 Jev（BYO-Key，$0.042/Mtok 输入、输出免费，≈$0.42/天@1 万次）。
- **反证据必须一起读**：按轮次换模型比"一个强模型跑到底"贵 **69.7%**；本地 Laya 选择器比零成本确定性规则贵 **8.8%**；jevgrep 把 Jev 成本降 59% 后合计仍贵 **2–3%**【仓库/代码·自测，笔记 03】。**"用决策模型省钱"目前是未经证实的承诺。**
- **生态可信度是本次调研最大的发现**：GitHub 上 `jev` 命中约 **1.4 万**仓库，绝大多数创建于 2026-09-15 之后；star 与提交数严重脱节（`laya-mlx` ★6,643 / 6 commits）；策展方自己在 README 里警告"同日批量提交、策展≠背书"；用户点名的 `16sulphur/laya-prompt-guard` **经查 404 不存在**，CSDN 同题文章里出现**不存在的模型名**（`jev-max`/`jev-mini`）。→ 本产品一律按**「有可运行代码 + 有 benchmark 产物 + 非全新账号的讨论」**三条采信，**不用 star 数与文章数量当成熟度**。

## 2. Jev 是什么（事实速查）

| 项 | 事实 | 档位 |
| --- | --- | --- |
| 端点 | `POST https://api.typesafe.ai/v1/systemone`，`Bearer` 鉴权；请求体 `{state, model, questions}`；**非 OpenAI 协议**，不能走 `chat/completions` | 【官方】01 |
| 三类问题 | **Noul**（返回 0–1，**不带 confidence**）｜**Choice**（≤255 选项，返回 probabilities + confidence）｜**Score**（2–10 级 + legend） | 【官方】01 |
| 限制 | 64k/请求；`state` + 最长问题 ≤32k（超限 422）；限流 **100K tokens/秒 且 40 请求/秒**，官方明示动态调整；错误码 401/422/429/**529 过载** | 【官方】01 |
| confidence 语义 | 由概率分布形状推导，**不是正确率**；校准是 group-level，不保证单条；官方**不给推荐阈值** | 【官方】01 |
| 定价 | **$0.042/Mtok 输入，输出免费**；无公开免费层（MCA 只保留"可有可无"的促销额度）；官方口径约 **$0.0399/1000 次决策**（950 tok/次） | 【官方】01 |
| 集成授权 | MCA **§2.1 明文允许**集成进自研应用供最终用户使用；**§2.4 要求凭据保密、不得共享** ⇒ 只能 BYO-Key（预置公共 Key 是违约风险） | 【官方】01 |
| 数据处理 | `state` 与问题**必然离开本机**；不以客户数据训练（除同意），但 **Telemetry 可无限制长期处理**；ZDR 仅企业版 | 【官方】01 |
| 语言与短板 | 英语为主，**"CJK 被支持但不同等好"**；官方自列 9 类失败：字面理解、**不会算数/计数**、日期比较、多跳、大 state 噪声、对抗内容、矛盾指令、常识不变量、生成任务 | 【官方】01 |
| 版本漂移 | 别名 `jev-latest` 会漂移；建议固定版本并记录响应 `model` 字段 | 【官方】01 |
| 渠道 | **Vercel AI Gateway 已上架 `typesafe-ai/jev`（零加价）**；OpenRouter 的 `typesafe/jev-router` 是**空壳**（无端点）；Cloudflare AI Gateway 无该 provider | 【官方】+【仓库/代码】01 |
| 中国大陆 | `api.typesafe.ai` 解析到 **Cloudflare 非中国节点**，未见于任何国内平台上架；**未能做大陆实测** | 【仓库/代码】+【推测】01 |

## 3. 免费与开源替代（省钱路的全部选项）

### 3.1 Laya（Convai Innovations）——生态里唯一"像产品"的开源基线

| 项 | 事实 |
| --- | --- |
| 形态 | 非自回归、**只做决策不生成文本**；三个 checkpoint：英文 421M、typed-decisions 421M、多语言 322M（默认 1024 token，可显式 8192）【仓库/代码，笔记 02】 |
| 许可 | **Apache-2.0**（可闭源商用）【仓库/代码】 |
| 体积 | GGUF/ONNX 量化约 **225–400 MB**（不同量化与来源；英文 Q4_K_M 实测 260 MB 上下，多语言版约 524 MB）【仓库/代码】 |
| 延迟 | T4：单问 32.8 ms、批 10 问 7.2 ms/问；CPU preload 后 193–464 ms（CPU 型号未标注）；**Core ML/ANE 有 P50 4.98 ms（M3 Max）的第三方数字**；**Apple Silicon 上跑 Laya 的官方实测缺失**【官方+第三方】 |
| 真实水平 | **零样本 typed-decisions 0.362，低于多数类基线 0.461**（官方模型卡自述）；微调后 0.766；Banking77（77 类）**42.5% vs Jev 87.0%**；钓鱼检测原始 recall **0.012**（AUROC 0.678 与 Jev 0.689 接近 ⇒ **排序基本对、阈值完全错**，Platt 缩放可修但温度缩放不行）【官方+第三方】 |
| 校准 | 官方自述**默认过度自信**：温度重拟合后 ECE 0.466→0.081，明说"先在自己的数据上校准再信概率"【官方】 |
| 运行时生态 | GGUF / ONNX / CoreML / MLX / LiteRT 量化齐全；`receptron/laya`（MIT，Node+ONNX，需 ~2 GB 内存）；**`ollaya`（Apache-2.0、Rust、自带 Tauri 2 桌面端）说 `/v1/systemone` 协议，macOS arm64 二进制 9.9–14.6 MB、权重按 sha256 从原作者 HF 拉取**——与本产品同技术栈，是"塞进桌面应用"最省事的一条【仓库/代码】 |

### 3.3 一条被低估的路线：借道用户已有供应商

不引入任何权重：用用户**已经配在 Switchelp 里**的供应商（含免费档小模型）跑"决策"，把结果当结构化判断用。成本：`gpt-5-nano` 约 **$0.27/天**（1 万次、300 in + 30 out）；智谱有官方标注免费的文本模型档（结构化输出与额度上限**未核实**）【官方价格 × 算术，笔记 06】。代价是**拿不到校准置信度**（LLM 的 token 概率不是校准概率），只能用于 argmax 场景或不参与门控。

## 5. 必须一起读的反证据与风险

1. **成本反噬**：+69.7%（按轮次路由）／+8.8%（本地 Laya 选择器 vs 确定性规则）／+2–3%（jevgrep 合计）。→ 路由类能力**默认只 shadow，不自动切换**。
2. **校准不可信**：高置信度答错（150 个扑克决策点仅 63% 与求解器一致，最错的答案 confidence 最高 0.86，且可复现）；量化后校准崩坏（39 条里 37 条是精确 0.0/1.0）；各模型最优阈值不同（0.35/0.70/0.95）；Laya 二分类要 **Platt 缩放而非温度缩放**。→ **阈值必须自测，不能抄**；界面不许把 confidence 写成正确率。
3. **中文更弱**：官方 CJK 原文口径；Banking77 中文/多类场景 42.5% vs 87.0%；B 站实测 14 条 SQL 只对 6 条。→ 中文场景用 multilingual checkpoint 或借道既有供应商，不承诺效果。
4. **隐私面**：中文圈最热的同类工具（聊天监控、回复助手）**大多把聊天记录整段发出网**；本产品的姿态是"不读会话内容"，任何要读正文的方案（上下文裁剪、工具门控）都必须显式授权、不持久化，并默认不做。
5. **官方数字口径不一**：自评倍数在自家博客（193.6×/444.6×）与创始人推文（40–200×）之间不一致，且无独立复现 ⇒ **不得进入产品界面**。
6. **条款与可达性**：禁蒸馏/竞品/多开领额度；`state` 必出网、ZDR 仅企业版；大陆无实测、未上架国内平台 ⇒ 托管 Jev **不得作为关键路径**。
7. **许可红线**：CC-BY-NC（`openjev` 系）、无许可证（`NanoJev`、`openjev-sglang`）、训练数据条款不清（`Jev-Style v3` 含受限条款与 OpenAI/Anthropic 输出）——**一律不打包、不引用**。

## 6. 落到 Switchelp：候选功能与优先级

与 [需求 01](../requirements/01-jev-feature-requirements.md) 的 P0/P1/P2 一一对应，此处只给"为什么是它"。

| 优先级 | 功能 | 落在哪个板块 | 为什么 | 靠什么数据 |
| --- | --- | --- | --- | --- |
| **P0** | 成本洞察（反事实成本/异常日/任务形态） | 用量页 | **零风险零成本**，不读会话内容、不出网、纯离线算术；生态里唯一"可信"的收益来自规则而非模型 | 已有用量解析 + 额度窗口；金额需用户自填单价，否则只出 token 差 |
| **P0** | 网关决策点骨架 + **shadow** | 网关 | 先拿到"若启用会怎么选"的真实数据再谈启用；state 只取非内容元数据（白名单闭集） | `RequestRoute` + 请求体的元数据键 + 现有额度窗口 |
| **P0** | 决策调用计量 | 用量页 | 回答"判断本身花了多少"；防止决策开销被混进对话用量（jevgrep 的教训） | 决策记录表（schema v4→v5） |
| **P0** | 上游错误归因（规则先行） | 网关/诊断 | 本产品被 502/400 误诊折磨过；**规则能覆盖的绝不用模型，灰区才问，绝不猜** | 既有规则表 + 结构化错误字段 + ≤120 字符脱敏摘要 |
| **P1** | 决策后端三选一（借道已有供应商 / 本地 Laya / 托管 Jev） | 设置 + 网关 | 让用户自选隐私与成本；**默认借道已有供应商**（$0–0.27/天、零体积、Windows 可用） | 既有凭据通路；本地权重走首次下载 + 现有 minisign 清单 |
| **P1** | 配额感知回退 | 网关 | 复用已解析的 `resets_at`；**默认只建议**，自动切换须显式开关 + 会话钉住 | `UsagePlanWindow` |

| **P1** | 插件安装前安全预检 | 插件中心 | SKILL.md 是短公开文本，天然适配决策模型；规则先挡破坏性命令 | `SkillDocument.body` |
| **P2** | 上下文证据裁剪 / 自然语言查询用量 | — | 前者要读会话内容（**默认不做**）；后者官方自认不会算数，只能"模型分类 + 代码计算" | — |
| **不做** | 自动切模型、读会话内容的门控、把决策模型包装成"智能体"、"换模型省钱"的承诺 | — | 均有反向实测或与产品底线冲突 | — |

## 7. 三条路线的成本与形态对照（决策用）

| | 借道用户已有供应商 | 本地 Laya | 托管 Jev |
| --- | --- | --- | --- |
| 1 万次/天成本 | **$0–0.27**（免费档则 $0） | **$0**（电费约 $0.0015/天） | **$0.42**（1,000 tok/次口径） |
| 分发体积 | 0 | **+260 MB**（首次下载，不随包） | 0 |
| 隐私 | 出网（走用户自己的供应商） | **不出网** | 出网（`state` 上传，ZDR 仅企业版） |
| 校准置信度 | **拿不到**（不参与门控） | 有，但需自己重拟合校准 | 有（choice/score；**noul 没有**） |
| 中文 | 取决于所选模型 | 需多语言 checkpoint，仍弱 | 官方自述"不同等好" |
| 大陆可用性 | 用户自己的供应商，通常最好 | 完全离线 | Cloudflare 非中国节点，**不可作关键路径** |
| Windows | 可用 | 理论可用（但更新/下载链路现缺） | 可用 |
| 备注 | **默认推荐** | 隐私档；记得 macOS 最低版本会从 12.0 抬到 13.3/14.0 | 仅 BYO-Key 开放 |

## 8. 未决问题（需拍板，详见两份下游文档）

1. **单价来源**：反事实金额用随包价格表还是用户自填？（建议用户自填，空则只出 token 差）
2. **本地推理是否进发行版**：随包（更新包 ×36）还是首次下载？macOS 最低版本抬不抬（ORT 需 14.0 / llama.cpp 需 13.3，现写 12.0）？
3. **托管 Jev 的定位**：大陆可达性未实测 ⇒ 只能作可选后端、BYO-Key。
4. **阈值从哪来**：官方不给、各项目 0.55–0.95 不等、各模型最优值不同 ⇒ 需要"贴样本自测"的向导，否则阈值就是编的。
5. **`design/07` §1.2「v1 不做成本估算」需要修订**：P0-1 正是它预留的"以后引入用户自填单价再单开一期"。
