# 安全、平台适配与运行运维

## 1. 威胁模型

保护对象是供应商 API Key、配置完整性和请求路由正确性。主要风险：renderer 被注入、日志泄漏、恶意网页调用 loopback、外部工具改配置、更新包被替换、请求被误路由。

系统凭据库保护静态存储，但不能阻止已经控制用户会话或高权限进程的攻击者；不宣传“绝对安全”。本项目默认不采集遥测，不读取其他应用的凭据或会话正文。

## 2. 密钥生命周期

1. 用户在专用密码输入框填入 Key；renderer 仅在提交所需时间短暂持有，提交后清空组件状态，不进入 localStorage、URL、DevTools 日志或持久化状态管理。
2. Rust 后端写 macOS Keychain 或 Windows Credential Manager；SQLite 只存引用、版本和掩码。
3. 后端解析为临时秘密值，仅提供给目标供应商请求，避免经命令行参数或子进程日志传递。
4. 替换 Key 创建新版本，在途请求保留旧版本；撤销时先停止分配新请求，再清理安全存储。
5. 凭据库不可用时明确失败，允许用户取消保存；绝不降级为明文 JSON。

默认不提供“显示已有完整 Key”；提供替换和检测。新输入可按住显示，离开输入框后重新隐藏。复制原 Key 不属于首发功能。掩码尾号仅作辨识，不当唯一 ID。

## 3. 本机认证与 IPC

本机访问令牌与上游 Key 分离；至少 256-bit 随机熵。令牌只授权特定实例的推理接口，不可用于管理供应商或读取文件。认证失败不返回模型列表。

command auth helper 从受限 IPC / 凭据服务取得令牌；helper 固定功能，不能接受任意文件路径或命令；stdout 仅令牌，stderr 仅脱敏错误。OS 用户身份校验是最低边界，同用户恶意进程仍是已知限制。

Loopback 校验 Host、Origin、Authorization 与方法/content-type。默认无跨域允许；拒绝浏览器 Origin 和预检来访（若将来开放 Web UI 必须独立方案）。只靠“127.0.0.1 不公开”不足以防恶意网页和 DNS rebinding。请求大小、并发数和速率均有有界限制。

## 4. URL 与网络

- 远程 endpoint 默认要求 HTTPS；只对显式本地 loopback 开放 HTTP。企业私网地址由用户明确配置，不能硬编码封禁所有私网。
- 解析 URL 后规范化尾斜杠，保留大小写敏感路径与 query；不得把完整 URL 转小写。
- 用户可能贴入完整 `/chat/completions` 地址：检测后展示建议 Base URL，不能悄悄拼成重复路径。
- 禁止 userinfo 中夹带密码/Key；敏感 query/header 转入安全引用。
- 默认不跟随携带 Authorization 的跨 origin 重定向；提示用户确认新地址。
- TLS 校验失败提供 CA/系统代理诊断，不提供默认“忽略证书错误”。
- 代理配置只作用本工具的上游网络客户端；不改变系统代理，不将 loopback 请求绕到远程代理。

## 5. 日志、备份和诊断包

日志允许：时间、operationId/requestId、模型内部 ID、供应商 ID、阶段、HTTP 状态、TTFT、耗时、Token 用量（如果上游提供）、错误 code、运行版本。默认不存 prompt、completion、工具参数、文件内容、Authorization、cookie、完整 URL query。

上游错误可能回显密钥，因此使用 allowlist 结构化提取，字符串脱敏为补充。错误截图若包含用户内容不自动收集。诊断包预览列出文件、敏感项处理和大小，再由用户保存到本地。

默认保留诊断事件 7 天或 20 MiB，先到为准；配置事务记录可保留 30 天。原始配置备份可能包含第三方工具写入的密钥：单独加密/权限保护，禁止混入脱敏包；普通预览仅显示遮罩。定期清理不得删除仍被恢复事务引用的备份。

## 6. 跨平台矩阵

| 首发架构 | arm64 | x64 |

| 应用数据 | `~/Library/Application Support/<app-id>` | `%LOCALAPPDATA%\<app-id>` |
| 凭据 | Security framework / Keychain | Credential Manager；必要时用户范围 DPAPI 封装，但只选一种清楚后端 |

| 替换文件 | 同目录临时文件 + fsync/rename | 原子替换 API + ACL 保留 + 有界占用重试 |

## 7. 启停与异常

关闭窗口默认保持服务，首次用非阻塞说明解释，可在设置改为退出。托盘始终保留重新打开入口。退出时若有请求，展示请求数量和“等待完成/立即退出”，不显示敏感内容。系统关机可能不给充足等待时间，因此每个请求和事务都需支持中断恢复。

睡眠唤醒后重新核对监听、凭据库状态、网络连接池和版本，不自动探测所有供应商。网关故障后受控恢复自身，最多 3 次退避；失败显示需要处理，不拉起 Codex 形成重启循环。

Codex 升级后对比 app/CLI/schema 指纹，未知版本进入“未验证”状态；保留现有原生路径，不自动安装旧版本或修改签名应用包。

## 8. 发布与更新

更新包签名、版本、平台、架构、校验和与渠道必须匹配。更新前有活跃流或配置提交则等待；升级前备份自己的 DB，记录可回退版本。禁止自动更新降低安全设置或重写用户配置。

依赖锁定、SBOM、许可证清单、漏洞扫描与签名证据纳入发布产物。商业分发是否可复用参考代码是单独工程门禁：没有项目级授权的部分采用独立实现；不复制竞争产品品牌和安装包资源。
