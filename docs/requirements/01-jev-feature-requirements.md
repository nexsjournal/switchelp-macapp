## 1. 文档定位与范围声明

**一句话：本文是需求，不是现状。** 它只回答两件事——「要做成什么样」与「做完怎么判断做完了」，不描述当前代码已经具备什么。

- 不写实现方案（属架构文档）、不写界面稿（属设计文档）、不写测试设计（属测试文档）。
- 凡本文与既有文档/实现冲突处：**冲突要显式登记并有人拍板，不许静默缩范围**；已知偏差一律以 `docs/README.md`「与文档的已知偏差」为准。
- 上游依据：六份调研笔记的**事实来源是公开 HTTP API、仓库/模型卡元数据与第三方公开评测**，未在本机安装或运行任何模型。引用数字必须带档位（见 §3.0），**不得把「项目自述」当「独立实测」**。
- 「未找到」≠「不存在」：调研期间通用搜索通道失效（`backend=none`、WebSearch 不可用），所有否证性结论都带这个前提。

**术语**：**决策模型** = 输入 `state` + 类型化问题，输出带校准概率的结构化判断、不生成文本的模型（托管 Jev / 本地 Laya / 用已有 LLM 充当的替代后端）；**决策点** = 被允许调用决策模型的位置；**决策调用** = 一次 `state` + `questions` 请求；**shadow** = 只记录「若启用会怎么选」、不改变实际路由。

**明确不在本文范围**：训练/微调任何模型；改变 Codex 本体行为；为决策模型新增任何内容采集；把决策模型当作出题/写作/代码生成工具。

## 2. 背景与目标用户、场景

**用户**：已经在用 Codex Desktop、手里有至少一个第三方供应商/中转 Key 的个人开发者（与产品定位一致）。他们不缺少判断力，缺少的是**可核对的事实**：这笔钱花在哪、这条报错是谁的问题、这个技能能不能装。

**为什么现在考虑决策模型**：Jev（TypeSafe，2026-09-15 发布）把「带概率的狭窄判断」做成了独立品类，并在两周内长出一整片兼容生态（托管 API 与本地开源两条路）。对本产品的意义是：**存在一类比 LLM 便宜两三个数量级、且不生成文本的判断服务**，可用于我们原本不敢做的地方（错误归因、内容筛选、安装前预检）。**风险同样明确**：生态极新（绝大多数仓库创建于 2026-09-16～24）、官方数字自评、已有多份反向实测（按轮次换模型反而更贵）。因此本文的第一条立场是**先记录、后启用**，而不是先上线。

**四个目标场景**（按确定性排序，与调研 03 §④ 的插入点排序一致）：

| 场景 | 用户问题 | 期望结果 |
| --- | --- | --- |
| S1 钱花在哪了 | 「这个月花了多少、哪几天不正常、换成便宜档会怎样」 | 全是估算，但**每个数字都能点开看来源** |
| S2 网关为什么失败 | 「502/400 到底是谁的问题」 | 有归因、有依据、**不知道就说不知道** |
| S3 谁在替我花钱 | 「我到底调了多少次判断、花了多少」 | 决策调用与对话调用分列计量 |
| S4 装进来的东西安全吗 | 「这个技能会不会让 AI 干坏事」 | 规则先挡，灰区才问，**永不静默安装** |

反场景（明确不追求）：用决策模型替用户省钱（有反向实测，见 §3.2）、替用户做决定（本来就不做）、把决策模型包装成「智能体」。

### 3.3 产品硬约束（团队规则，需求必须服从）

1. **不做假开关**：核心层没实现的控件不做；界面要直说原因（已有先例：预设接口因恒返回空而整体删除）。
2. **界面不读用户会话内容**：「不记内容」是既定姿态；任何要读会话正文的需求默认不做，仅作为需显式授权的未来项记录。
3. **文案中英双语键集合一致**：每条新增文案必须同时在 zh/en 两侧落键，键集合一致。
4. **反馈只有 Toast 一个出口**：动作结果走 Toast；页面状态（读不到数据、网关未启动）留在页面内联条；不新增反馈表单/横幅。
5. **不暗示、不猜**：不展示没有可靠来源的金额、余额、成功率、节省率；不把估算渲染成实测。

### 3.4 由此推出的三条设计约束（本文的「红线」，后续所有需求都受其约束）

- **R1 默认关闭 + 只建议**：任何改变实际路由/实际安装结果的能力默认关闭；先产出可核对的记录，再谈启用。
- **R2 fail-open（网关侧）/ fail-closed（安全侧）**：网关路径上决策模型报错、超时、低置信一律走原路径，绝不阻断 Codex 请求；安装前预检的失败一律落回「询问用户」，绝不静默放行。
- **R3 无依据不显示**：每个展示出来的概率、金额、归因都必须带来源与档位；数字不可得时显示「—」并写明原因，不显示 0。

## 4. 功能清单

### 4.1 P0（首次可用必须包含；**契约已定，不增不减**）

#### P0-1 用量页「成本洞察」（离线、只读、纯规则）

| 维度 | 内容 |
| --- | --- |
| 用户价值 | 把已解析的用量与额度窗口变成「钱花在哪、哪几天不正常、换档会怎样」；回答 S1。**这是最容易被信任的一页——只要它不撒谎。** |
| 前置条件 | ① 单价来源必须先定：随包价格表（带核实日期、可被更新）或用户自填，二者至少一项；② 复用既有 `UsageTotals/UsageDay/UsageModelRow/UsageProviderRow` 与 `UsagePlanWindow{plan_type,used_percent,window_minutes,resets_at}`，**不新增任何会话内容读取**。⚠ 与 `design/07-usage-page.md` §1.2「v1 明确不做成本/金额估算」**直接冲突，需先修订该条**（本条正是它预留的「以后引入用户自填单价再单开一期」）。 |
| 隐私影响 | 无新增出网、无新增落盘：全部在本机已解析结构上做算术。界面不得因此读取消息正文。 |
| 成本影响 | $0（不调用任何模型/接口）。 |
| 做不好的坏结果 | 用户看到一个精确但无出处的金额，据此改了供应商——**这是本产品最容易失信的地方**（生态里 jevgrep/0xNatoshi/miniLV 三家都在为此自辩）。 |
| 可验收标准 | ① 每一处金额旁有「估算」标记，可展开看到**单价、来源、核实日期**；无单价的模型显示「—」并说明原因。② 反事实口径显式：只换单价、不假设行为变化，界面写明「同一 token 量按 X 单价计算，不代表换档后实际用量不变」；给出差额而非「已省」。③ 异常日只用**确定性统计规则**（如 30 日滚动分位数/中位数倍数），界面显示规则与阈值；**该功能不得调用任何模型**（可用一次 e2e 断言：开启后无任何决策调用计数）。④ 任务类型归类只允许用**已解析的元数据白名单**（模型、供应商、日期、会话轮次/token 构成、是否 reasoning、cwd 的仓库标识），结果标注「基于元数据的启发式，不是内容分类」；不给结论时显示「未归类」，**不猜**。⑤ 负向证据：把一条只存在于会话正文里的哨兵字符串，在该功能的所有落盘文件与日志中 grep 必须为 0 命中。⑥ 90 天/本机现有 337 文件规模下页面可用，且合计与各维度之和一致（差值为 0）。 |

#### P0-2 网关决策点骨架 + shadow 模式

| 维度 | 内容 |
| --- | --- |
| 用户价值 | 拿到「若启用会怎么选」的真实数据，再决定要不要启用；回答「这个决策点值不值」而不是先斩后奏。 |
| 前置条件 | ① 决策服务契约必须先定义（能表达 Choice/Score/Noul、probabilities、confidence、usage、model 版本、失败与超时）；② 决策点位置在网关 `Admission` 通过、拿到 `RequestRoute` 之后、转发上游之前；③ **state 只允许非内容元数据**：模型别名、上下文分桶、工具名、错误摘要、轮次、配额窗口——固定白名单，写进契约。 |
| 隐私影响 | 无新增出网（shadow 阶段可只用规则/本地判定）；记录不得含正文与工具输出原文。 |
| 成本影响 | 默认 $0（shadow 允许先只记「规则版会怎么选」）；接后端后按 P0-3 计量。 |
| 做不好的坏结果 | 要么变成「没人看的日志」；要么一旦默认开启并改路由，用户看到模型被悄悄换掉、prompt cache 失效、账单变高（**有 +69.7% 的反向实测**）。 |
| 可验收标准 | ① **默认关闭**；关闭时上游请求体、路由结论、`routeRevision/credentialVersion` 与现状逐字节一致。② 开启 shadow 后，请求与路由**不变**，但每条记录含：state 字段清单、问题与类型、返回概率、confidence（**Noul 记 null，不伪造**）、耗时、后端标识、`model` 版本字段。③ 决策侧超时/报错/结构非法时请求照常成功（fail-open），失败计数在内联条可查、不刷屏、不写 Toast 噪声。④ 契约能表达三类问题，且「后端返回 Noul」时全链路显示「—」而不是 0 或 1。⑤ 负向证据：注入哨兵字符串到会话正文，shadow 记录文件中 0 命中。⑥ 可一键导出记录（JSONL），供 P1 新增-1 复核。 |

#### P0-3 决策调用计量

| 维度 | 内容 |
| --- | --- |
| 用户价值 | 回答 S3：决策调用与对话调用**分开计量**，看清「判断本身」花了多少。 |
| 前置条件 | 依赖 P0-2 的记录模型；成本口径需与 P0-1 共用同一份单价来源。 |
| 隐私影响 | 无（只统计计数与 usage 数字）。 |
| 成本影响 | $0（计量本身不产生调用）。 |
| 做不好的坏结果 | 决策调用被混进「对话用量」合计，用户既看不懂也无法做取舍；或把本地推理显示成 $0.00 与在线 $0.02 并列，制造「免费幻觉」。 |
| 可验收标准 | ① 出现独立的「决策调用」计量：**次数、输入 token、估算成本、低置信度占比**，且**不污染**既有四个 token 指标与「按模型/按供应商」合计。② 低置信度占比的分母是「返回了 confidence 的问题数」，Noul 不计入分母，页面有一行说明。③ 区分**本地模型**（显示「本地推理，无 API 费用」而非 `$0.00`）与**在线服务**（显示单价来源与日期）。④ 失败调用单列（失败次数），不计入成功次数与 token 合计。⑤ 数字可核对：人工触发一次已知响应的决策调用，界面显示的输入 token 与响应 `usage.input_tokens` 相等。⑥ 文案中英键集合一致（见 §3.3-3）。 |

#### P0-4 上游错误归因

| 维度 | 内容 |
| --- | --- |
| 用户价值 | 回答 S2：把 4xx/5xx 归到 `auth / protocol_translation / quota / upstream / unknown`。本产品**历史上被 502/400 误诊折磨过**，这条是止损需求，不是锦上添花。 |
| 前置条件 | 规则表先行（`401/403→auth`、`429 或含额度字段→quota`、`5xx/DNS/TLS→upstream`、`400/422 带字段级报错→protocol_translation`），与既有 §7 错误分类表对齐；模型只处理规则未覆盖的灰区。 |
| 隐私影响 | state 仅错误元数据（状态码、供应商名、上游 `error.code/type`、**截断脱敏后的** message 片段、请求路径、是否流式、是否含 tool call、重试次数）；**绝不含会话内容**。 |
| 成本影响 | 灰区才调用（错误文本很短）；规则命中 $0。 |
| 做不好的坏结果 | 用户按错误归因去换 Key/改配置，而真实原因在别处——**本产品最贵的一类错误就是「自信地指错方向」**。 |
| 可验收标准 | ① 规则命中时**零模型调用**（可用一次上游错误 fixture 断言调用计数为 0）。② 每条归因显示**依据**：命中的规则条目 / 模型 + 概率 / 「无法判定」。③ 模型不可用、超时、返回非法结构或低置信 → 归为 `unknown`，**原样展示上游报文**并给「复制原始报文」按钮；不新增反馈表单（反馈出口只允许 Toast）。④ 归因结果**不触发任何自动动作**（不换 Key、不改配置、不自动重试非幂等请求），只给建议。⑤ 回归证据：把已发生的 502/400 误诊案例固化成 fixture，归因必须给出正确类目，或在信息不足时给 `unknown`——**宁可 unknown，不可猜**。⑥ 「协议翻译」类必须给字段级线索（哪个字段/角色/shape 不兼容），而不是只说「协议问题」。 |

## 5. 不做清单（含理由）

| 不做 | 理由 |
| --- | --- |
| 自动改用户配置 / 自动切模型而未经确认 | 有 +69.7% 的反向实测；且原生行为变更必须可解释、可恢复（产品既有姿态） |
| 读会话内容做工具门控或自动批准 | 权限层归 Codex 所有，不归本产品；提供商自认对抗输入可影响分类器 → 门控只能是加速器，不能是最后防线 |
| 把决策模型包装成「AI 智能体」 | 它不生成文本、不做调度；且**不得让 Agent 的解释冒充模型的原始输出**（社区正确姿势：不执行推荐动作、不自动路由） |
| 为用 Jev 而用 Jev | 免费额度页/用量归因/额度有效性抽取等，规则实现更可靠、更可解释（调研 04 已逐条劝退） |
| 引用未验证的批量空壳项目 | 生态存在同日批量发布、star 与提交脱节、README-only 仓库；`16sulphur/laya-prompt-guard` 根本不存在；CSDN 内容含虚构模型名 → 只采信「可运行代码 + benchmark 产物 + 非全新账号讨论」 |
| 在界面里放没有真实实现的开关 | 团队硬规则；已有先例（恒返回空的预设接口被整体删除） |
| 用「换模型省钱」做承诺/营销 | 反向实测在先；本地推理的省钱上限 <$1/天（1 万次量级），它是**隐私选项**不是省钱选项 |
| 用决策模型做算术、计数、日期比较、长文生成 | 官方自认短板（model-jaggedness 9 类），这类活交给代码 |
| 内置/共享一把公共 Key；打包 CC-BY-NC、无许可证、训练数据条款不清的权重 | MCA §2.4 凭据保密；`openjev`（CC-BY-NC-4.0，GGUF 仓许可自相矛盾）、`NanoJev` 权重无 license、`openjev-sglang` 无许可证、`Jev-Style v3` 训练数据含受限条款与 OpenAI/Anthropic 输出 |
| 引用未经复现的官方倍数（193.6×/444.6×）；把估算写成实测；用 star 数当成熟度 | 会直接摧毁信任，而信任是本产品唯一的护城河 |

| M6 | P1-6/7/8 + N1/N2/N3 | M5（7/8 可用规则路径先上，模型后接） | 各自验收全绿；N1 必须给出「启用 vs 不启用」的可核对结论 |

## 7. 成功标准

1. **能回答**：M1 后，用户在 90 天数据上能回答「哪几天不正常、换档大约差多少」，且页面上**没有一处金额缺来源**。
2. **能决策**：M2+M3+N1 后，团队能用 shadow 数据得出「这个决策点启用/不启用」的结论，**并且允许结论是「不启用」**——成功是「有数据支撑的决定」，不是「上线了路由」。
3. **不撒谎**：全链路无「估算写成实测」、无「confidence 当正确率」、无未标注来源的金额与倍数；Noul 处一律「—」。
4. **不添乱**：三处决策点在失败/超时/低置信下的行为与 R2 一致（可用故障演练复现）；决策调用成本可被上限约束，且其成本占被决策工作流成本的比例**有实测数字**（当前未定，需 M3 后给出）。
5. **不违背**：新增文案中英键集合一致；反馈只走 Toast；界面不读用户会话内容。

## 8. 风险与未决问题

| # | 风险 / 未决 | 现状与应对 |
| --- | --- | --- |
| 1 | **校准不可信** | 官方：校准是 group-level，不保证单条；无推荐阈值。实测：高置信度答错（扑克最错者 0.86）；量化后校准崩坏（37/39 条精确 0.0/1.0）；Laya 需在自己的数据上重拟合（ECE 0.466→0.081）、二分类用 Platt 而非温度缩放。→ 阈值必须自测（N4）；门控只能是加速器；UI 不出现「置信度=正确率」的措辞。 |
| 2 | **中文/CJK 表现弱** | 官方原文「CJK handled but not equally well」；Laya 早期 checkpoint 仅英文、多语版默认 1024 token 会截断长文；Banking77 42.5% vs Jev 87.0%、14 条 SQL 只对 6 条。→ 中文场景必须自测；文案不得承诺中文效果；选项数超 ~20 需两级选择。 |
| 3 | **中国大陆可达性** | `api.typesafe.ai` 解析到 Cloudflare 非中国节点；站点启用了 Bot Management（调研沙箱出口 IP 被 403）；未见任何国内云厂商上架；**无法从大陆网络实测**（整体判为「结构性证据 + 推测」）。→ 在线 Jev **不得作为关键路径**；默认后端必须是「本地或用户已有供应商」；任何在线后端都要可一键关掉并回退。 |
| 4 | **许可与合规** | MCA §2.1 允许集成进自研应用，§2.4 要求凭据保密（BYO-Key 是合规必需而非可选项）；禁止蒸馏/竞品/多开账号；`state` 必然出网、ZDR 仅企业版、Telemetry 无限制。权重侧：CC-BY-NC/无许可/训练数据条款不清三类一律不打包。→ 发布门禁为模型权重增列「仓库 ID / 文件 / sha256 / 许可 / 底座许可链 / 训练数据声明」。 |
| 5 | **空壳与灌水污染技术判断** | 生态仓库 9 天内批量生成、star 不可信、HN/Reddit 有推广指控、CSDN 内容与官方定义冲突。→ 只按「可运行代码 + benchmark 产物 + 非全新账号讨论」采信；本文不引用任何未核实的批量项目。 |
| 6 | **成本收益可能不成立** | 反向实测：子代理路由 +69.7%、本地 Laya +8.8%、jevgrep 含 Jev 合计 +2–3%。→ 路由默认关；N3 预算与熔断；成功标准允许「不启用」。 |
